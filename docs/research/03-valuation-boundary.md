# 밸류에이션 경계 재설계

근거: [04-BENCHMARK-ANALYSIS.md](../research/01-benchmark-smic.md) §4 (밸류에이션 로직 해부), §5 (추정 모델 정밀도)

## 1. 무엇을 고치는가

[00-PRD.md](../surfaces/ra-tool-v0/prd.md) 원칙 2는 이렇게 되어 있습니다:

> **원칙 2 — 투자의견은 사람이 입력한다.** 목표주가와 투자의견은 리포트에 들어갑니다. 그러나 시스템은 이것을 생성하지 않습니다.

방향은 맞습니다. 그러나 **선을 너무 위에 그었습니다.** "목표주가를 생성하지 않는다"를 "밸류에이션을 다루지 않는다"로 확대해석해서, 계산에 불과한 작업까지 전부 포기했습니다.

벤치마크 15건 전부가 목표주가를 산출합니다(14/15건 명시). 그 산출 과정의 대부분은 **판단이 아니라 계산**입니다.

## 2. 새 경계 — 판단은 가정에만 있다

핵심 원리:

> **사람은 가정을 정한다. 코어는 가정의 결과를 전개한다.**

가정이 정해지면 그 뒤는 전부 산술입니다. 산술을 사람이 엑셀로 하는 게 현재의 낭비입니다.

### 판단 (사람 전용, 시스템이 생성 불가)

| 항목 | 왜 판단인가 |
|---|---|
| 드라이버 가정 (ASP 상승률, 물량 증가율, 가동률) | 산업 전망. 공시에 없음 |
| Target Multiple 채택값 | "어느 과거 구간이 현재와 유사한가"는 서사 판단 |
| 시나리오 분기 정의 | "누르기방지법이 통과되면"은 정책 전망 |
| 할인율 수준 | 리스크 인식 |
| 최종 목표주가 · rating | 위 전부의 종합 |

### 계산 (결정론 코어가 제공)

| 항목 | 입력 | 출력 |
|---|---|---|
| 3표 추정 전개 | 드라이버 가정 | 손익 → BS → CF 연결 |
| 멀티플 밴드 작성 | 가격 시계열 + 추정 EPS/BPS | 12M Fwd PER/PBR 밴드 |
| 밴드 구간 통계 | 밴드 + 구간 지정 | 평균·중위·분위 |
| PBR 분해 | PDR·ROE·배당성향 중 3개 | 나머지 1개 (§3) |
| 내재 할인율 역산 | 현재가 + 이론가 | 할인율 |
| SOTP 합산 | 사업부별 가치 | 합계 + 순현금 조정 |
| 시나리오 전개 | 분기 정의 + 가정 세트 | 케이스별 목표주가 경로 |
| 교차 검증 | 두 방법의 결과 | 차이 및 정합성 경고 |
| Peer 비교표 | peer 목록 | 멀티플 대조 |
| 상승여력 | 목표주가 + 현재가 | % |

## 3. PBR 분해는 항등식입니다

벤치마크 사례(금화피에스시)가 쓰는 분해:

```
PBR = PDR × ROE × 배당성향
```

수치 검증했습니다. 정확히 성립합니다:

```
PDR × ROE × payout
  = (P/D) × (NI/BV) × (D/NI)
  = P/BV
  = PBR                          ∎
```

**이건 근사가 아니라 항등식입니다.** 제품 함의:

- 4개 값 중 **3개를 입력하면 나머지 1개가 결정**됩니다
- 사용자가 4개를 모두 손으로 넣으면 **모순이 발생할 수 있고, 시스템이 그것을 잡아야 합니다**
- 벤치마크 리포트가 "ROE는 자동으로 계산되게 된다"고 직접 서술한 것이 이 구조입니다

마진 브리지의 `reconciliation`과 같은 성질입니다. 계산이 닫히는지 검산하고, 안 닫히면 표시합니다. 기존 `edgar_financials.py`의 브리지 검산 패턴을 그대로 재사용할 수 있습니다.

## 4. 데이터 의존성 — 밴드는 가격 시계열이 필요합니다

**이게 이 설계의 조달 병목입니다.**

12M Fwd PER 밴드를 그리려면:

| 필요 | 출처 | 현재 확보 |
|---|---|---|
| 과거 주가 시계열 (일별, 3~5년) | 유료 데이터 또는 거래소 | ❌ |
| 시점별 12M Forward EPS | 컨센서스 이력 (유료) 또는 자체 추정 이력 | ❌ |
| 발행주식수 이력 | 공시 | ✅ (SEC/DART) |
| 실적 BPS | 공시 | ✅ |

벤치마크 사례에서 Target Multiple의 근거가 **자기 역사적 밴드**였으므로, 가격 시계열 없이는 밸류에이션 기능의 핵심이 성립하지 않습니다.

우회 경로와 한계:

| 방안 | 가능 여부 | 한계 |
|---|---|---|
| Trailing PER 밴드 (실적 EPS 기준) | 가격만 있으면 가능 | 벤치마크는 Forward를 씀. 성장주에서 의미 차이 큼 |
| 자체 추정 이력으로 Forward 구성 | 시간이 쌓이면 가능 | 초기에는 데이터 없음 |
| 컨센서스 이력 구매 | 가능 | 비용. 해외 종목은 특히 |
| Peer 멀티플 비교로 대체 | 즉시 가능 | 벤치마크의 실제 논거와 다름 |

**[00-PRD.md](../surfaces/ra-tool-v0/prd.md) §11에 오픈 아이템으로 추가해야 합니다.** 가격 데이터 조달 없이 밸류에이션 기능을 약속하면 안 됩니다.

## 5. 산출물 계약 — 원칙 2를 어기지 않으면서 계산을 제공하는 방법

계산 결과에는 항상 **가정의 출처**가 붙습니다. Numeric Token Binding의 확장입니다.

```json
{
  "ai_generated_opinion": false,
  "valuation": {
    "method": "per_forward",
    "computed_by": "deterministic_core",
    "target_price": { "value": 8610, "currency": "TWD" },
    "upside_pct": 67.5,
    "inputs": [
      {
        "field": "eps_2027e",
        "value": 143.73,
        "source": "estimate_model",
        "model_version": 7,
        "assumption_owner": "user_8f2a"
      },
      {
        "field": "target_multiple",
        "value": 59.91,
        "source": "human_assumption",
        "basis": "band_window",
        "band_window": { "from": "2023-07", "to": "2024-01", "stat": "mean" },
        "computed_band_value": 59.91,
        "entered_by": "user_8f2a"
      }
    ],
    "formula": "target_price = eps_2027e * target_multiple",
    "scenarios": [
      { "label": "HBM 반영", "target_multiple": 59.91, "target_price": 8610 },
      { "label": "HBM 미반영", "target_multiple": 53.40, "target_price": 7675 }
    ]
  },
  "investment_opinion": {
    "source": "human_analyst",
    "rating": "BUY",
    "target_price": 8610,
    "entered_by": "user_8f2a",
    "entered_at": "2026-07-30T05:22:11Z"
  }
}
```

핵심 장치:

1. `valuation.computed_by: "deterministic_core"` — 계산은 코어가 했음을 명시
2. 모든 입력에 `source` 태그: `estimate_model` / `human_assumption` / `sec_fact`
3. `target_multiple`은 `human_assumption`이지만 `computed_band_value`가 함께 기록 — **사람이 밴드 통계를 채택했다**는 사실이 추적됨
4. `investment_opinion`은 여전히 사람 입력이고 별도 필드 — **계산된 `valuation.target_price`를 자동 복사하지 않습니다.** 애널리스트가 명시적으로 채택해야 합니다
5. `ai_generated_opinion: false` 불변

### 왜 자동 복사를 막는가

계산된 목표주가를 의견 필드에 자동으로 넣으면, 실질적으로 시스템이 목표주가를 제시하는 것이 됩니다. 계산은 제공하되 **채택 행위는 사람의 명시적 클릭**이어야 합니다. 그 클릭이 감사 로그에 남습니다.

## 6. LLM의 역할 — 밸류에이션에서는 없음

**밸류에이션 경로에 LLM을 넣지 않습니다.**

- 숫자는 전부 결정론 계산 또는 사람 입력
- LLM은 밸류에이션 **결과를 서술**할 때만 개입하고, 그때도 Numeric Token Binding 규칙을 그대로 적용
- 즉 LLM은 `{{val:target_price}}`, `{{val:upside_pct}}` 토큰만 쓸 수 있음

이유: 밸류에이션은 리포트에서 가장 규제 민감하고 가장 검증 가능한 영역입니다. 확률적 생성이 개입할 이유가 없습니다.

## 7. 원칙 2 개정안

기존:

> 목표주가와 투자의견은 리포트에 들어갑니다. 그러나 시스템은 이것을 생성하지 않습니다.

개정:

> **원칙 2 — 사람은 가정을 정하고, 시스템은 결과를 전개한다.**
>
> 투자의견과 최종 목표주가는 애널리스트가 명시적으로 채택하며, 시스템이 생성하거나 자동 기입하지 않습니다. 동시에 시스템은 밸류에이션 **계산**을 온전히 제공합니다 — 3표 전개, 멀티플 밴드, 분해 항등식, 시나리오 전개, 교차 검증. 모든 계산 결과에는 입력 가정의 출처(`estimate_model` / `human_assumption` / `sec_fact`)가 붙습니다.
>
> 판단은 가정에만 있습니다. 가정의 산술적 귀결을 사람이 손으로 계산하게 두는 것은 제품의 실패입니다.

## 8. 구현 범위와 선후

| 항목 | 선행 조건 | Phase |
|---|---|---|
| PBR 분해 항등식 + 검산 | 없음 (순수 산술) | 1 |
| SOTP 합산 + 순현금 조정 | 세그먼트 데이터 | 2 |
| 3표 추정 전개 | 추정 워크벤치 | 2 |
| Peer 멀티플 비교표 | peer 목록 + 실적 | 2 |
| 시나리오 전개 | 추정 워크벤치 | 2 |
| **멀티플 밴드** | **가격 시계열 조달** | **미정 (블로킹)** |
| 내재 할인율 역산 | 가격 시계열 | 미정 |

밴드가 블로킹이므로, Phase 1에서는 **분해 항등식과 검산**부터 시작합니다. 이건 데이터 의존성이 없고 즉시 가치가 있습니다.
