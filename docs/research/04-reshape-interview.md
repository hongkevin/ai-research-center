# Reshape — 제품 형태와 인터뷰 설계

## 1. 문제 제기

지금까지의 설계([00](../surfaces/ra-tool-v0/prd.md)~[06](../research/03-valuation-boundary.md))는 전부 **process-preserving optimization**입니다.

| 설계 | 대체 대상 | 성격 |
|---|---|---|
| Fact Layer | 수동 공시 조회 | 같은 작업, 빠르게 |
| 추정 워크벤치 | 엑셀 3표 모델링 | 같은 작업, 빠르게 |
| 초안 에디터 | 글쓰기 | 같은 작업, 빠르게 |
| Revision 추적 | (없던 것) | 관리 레이어 추가 |

기존 프로세스를 소여로 받고 그 안에서 마찰을 줄였습니다. AX 관점의 Reshape — 프로세스 자체를 AI Native하게 재정의하는 것 — 이 아닙니다.

## 2. 다만 이분법으로 놓으면 실패합니다

이 도메인에는 **진짜로 고정된 것**이 있습니다. 그것과 싸우는 Reshape는 제품을 죽입니다.

### 고정 — 제도·시장이 정함

| 항목 | 근거 | 바꿀 수 있는 주체 |
|---|---|---|
| 준법감시인 심사 | 자본시장법·내부통제 | 규제당국 |
| 애널리스트 서명 책임 | 자본시장법 | 규제당국 |
| PDF 리포트 형식 | 기관 고객 소비 관행 | 시장 전체 |
| KOFIA 괴리율 공시 | 제도 | 협회 |
| FnGuide 종목별 채점 (최소 3종목) | 평가 기관 | 평가 기관 |
| 매수 편향 93.1% | 발행사 관계·IB·법인영업 | 산업 구조 |

**1인 스타트업이 바꿀 수 없습니다.** "리포트를 없애고 실시간 대시보드로 대체하자"류의 제안이 실패하는 지점입니다.

### 인위적 — 인간 처리량이 정함

| 항목 | 왜 그런가 |
|---|---|
| **RA 1명당 모델 10~15개** | 종목마다 3표 모델을 손으로 만들고 유지 |
| 분기 실적 후 수동 갱신 | 데이터 파이프라인 부재 |
| 리포트가 시점 스냅샷 | 갱신 비용이 높아서 |
| 커버리지 개시 비용이 높음 | 모델을 처음부터 세워야 함 |
| 상장사 70% 무커버 | 위 전부의 귀결 |

**전부 하나로 수렴합니다.**

## 3. 붕괴시킬 제약

> **RA 1명이 유지할 수 있는 추정 모델 수 = 10~15개**

제도가 정한 게 아니라 **손으로 만들고 손으로 갱신하기 때문**에 생긴 한계입니다.

### 붕괴 시 연쇄 효과

| 결과 | 현재 불가능한 이유 |
|---|---|
| 커버리지 3~5배 확장 | 모델 유지 비용 |
| **논지 단위 커버리지** — "AI 병목이 전력으로 이동"에 걸린 40종목을 한 번에 | 40개 모델을 못 세움 |
| 커버리지 개시 비용 급감 → **무커버 70% 시장 진입** | 개시가 가장 비쌈 |
| 추정 정확도 상시 관리 | 수가 적어야 손으로 추적 가능 |

### 제도와 충돌하지 않습니다

- 사람이 여전히 판단하고 서명하고 심사받습니다
- FnGuide 3종목 요건은 오히려 **쉽게 충족**됩니다
- 리포트는 여전히 PDF로 나갑니다
- [05-REPORT-QUALITY.md](../research/02-report-quality.md) §3.5의 "내부 정직 / 대외 판단 분리" 원칙이 그대로 유지됩니다

**Reshape의 대상은 프로세스 전체가 아니라 처리량 제약 하나입니다.** 그것만 붕괴시키면 프로세스가 스스로 재정의됩니다.

## 4. 제품 형태

단위가 바뀝니다.

```
현재 설계    리포트 작성 도구         단위 = 리포트 1건
   ↓
Reshape 후   커버리지 운영 시스템      단위 = 커버리지 포트폴리오
```

### RA 역할의 전환

| | 현재 | AI Native |
|---|---|---|
| 하는 일 | 모델을 **만든다** | 모델을 **감독한다** |
| 처리량 | 10~15종목 | 40~60종목 (가설) |
| 갱신 | 분기마다 수동 | 공시 감지 → **자동 갱신 제안** → 검토·승인 |
| 승인 이력 | 없음 | **그 자체가 정확도 추적 데이터** |
| 시간 배분 | 데이터 정리 + 모델링 + 작성 | 가정 검토 + 이상치 판단 + 논지 구성 |

마지막 줄이 Reshape의 실질입니다. **사람이 하는 일의 종류가 바뀝니다** — 산술에서 판단으로.

### 승인 흐름이 곧 감사 추적입니다

별도 기능이 아닙니다:

```
공시 감지 → 자동 갱신 제안 → RA 검토
                                ↓
                    ┌───────────┴───────────┐
                  승인                     반려·수정
                    ↓                       ↓
            추정 스냅샷 확정          가정 변경 기록
                    ↓                       ↓
            └──────── 정확도 이력 / revision 이력 ────────┘
                                ↓
                    실적 발표 → 자동 채점 (FnGuide 40점 지표)
```

[05-REPORT-QUALITY.md](../research/02-report-quality.md) §3(revision discipline)과 §3.5(정합성 표시)가 이 흐름의 부산물로 자동 확보됩니다.

### 기존 발견들이 여기로 수렴합니다

| 발견 | 출처 | 커버리지 OS에서의 위치 |
|---|---|---|
| 추정이 핵심 (FnGuide 40점) | [05](../research/02-report-quality.md) §1 | 시스템의 중심 객체 |
| Revision discipline | [05](../research/02-report-quality.md) §3 | 승인 흐름의 부산물 |
| 정합성 표시 (C안) | [05](../research/02-report-quality.md) §3.5 | 갱신 제안 시 자동 표시 |
| 무커버 70% | [05](../research/02-report-quality.md) §5.2 | 처리량 붕괴의 직접 수혜 |
| 세그먼트·P·Q 분해 | [04](../research/01-benchmark-smic.md) §2 | 모델의 드라이버 구조 |
| 8-K/CFO Commentary | [04](../research/01-benchmark-smic.md) §6 | 자동 갱신의 트리거·입력 |

전부 "리포트 1건 잘 쓰기"가 아니라 **"N개를 항상 최신으로 유지하기"**를 가리키고 있었습니다.

## 5. 이 방향의 위험

| 위험 | 내용 | 완화 |
|---|---|---|
| **구매자 전환** | 커버리지 배정은 조직이 함. 개인 seat로는 확장이 성립 안 됨. 조직 판매는 사이클이 김 | 개인은 "내 종목 깊게", 조직은 "커버리지 확장"으로 이중 가치 제안 |
| **신뢰 선행 문제** | AI 추정을 승인하려면 먼저 믿어야 함. 초기 정확도가 낮으면 **검토 비용 > 작성 비용** | 기존 모델 임포트 → 재현 검증부터. 신규 생성은 그 다음 |
| 업종 이질성 | 3표 연결 규칙이 업종마다 다름 | 업종 템플릿. 미검증 업종은 `limited` 표시 |
| 감독의 함정 | 승인 버튼만 누르는 형식적 검토 → 정확도 하락 | 이상치·가정 변경만 강조 표시. 전체 승인 금지 |
| **전부 미검증** | 처리량이 진짜 병목인지 확인 안 됨 | **인터뷰 (§6)** |

## 6. 인터뷰 설계

### 원칙 — 묻지 말아야 할 질문

> ❌ **"AI가 뭘 해주면 좋겠어요?"**

사용자는 자기 프로세스 안에서만 상상합니다. 현재 작업의 부분 자동화 아이디어만 나옵니다. Reshape 정보를 얻을 수 없습니다.

Reshape 인터뷰는 **제약을 탐지**합니다.

### A. 실측 — 현재 프로세스 이해 (30분)

| # | 질문 | 얻는 것 |
|---|---|---|
| A1 | 지난 분기 실적 시즌 일주일을 시간 단위로 재구성해 주십시오 | 실제 시간 배분 (기억이 아닌 재구성) |
| A2 | 커버 종목 몇 개입니까? 그중 모델을 실제로 유지하는 건 몇 개입니까? | **차이가 있으면 이미 처리량 한계** |
| A3 | 종목 하나 모델을 처음부터 세우는 데 얼마나 걸립니까? | 개시 비용 |
| A4 | 분기 실적 후 모델 갱신에 얼마나 걸립니까? | 유지 비용 |
| A5 | 그 시간 중 판단이 필요한 부분과 기계적인 부분의 비율은? | 자동화 여지 |

### B. 제약 탐지 — Reshape의 핵심 (30분)

| # | 질문 | 얻는 것 |
|---|---|---|
| **B1** | **커버 종목이 지금의 3배가 되면 무엇이 가장 먼저 무너집니까?** | **진짜 병목.** 이 답이 제 가설과 다르면 방향 전환 |
| B2 | 모델 유지에 시간이 전혀 안 든다면 남는 시간에 무엇을 하시겠습니까? | 억눌린 수요 |
| B3 | 커버하고 싶은데 못 하는 종목이 있습니까? 이유는? | 무커버 시장의 실제 장벽 |
| B4 | 안 해도 아무도 모를 작업이 있습니까? | 폐기 후보 |
| B5 | 지금 하는 일 중 "이건 사람이 할 일이 아닌데" 싶은 게 있습니까? | 자동화 우선순위 |
| B6 | 애널리스트가 RA에게 가장 자주 하는 요구는? | 실제 산출물 정의 |

### C. 신뢰와 승인 — 제품 형태 검증 (20분)

| # | 질문 | 얻는 것 |
|---|---|---|
| C1 | 남이 만든 추정 모델을 넘겨받아 쓴 경험이 있습니까? 어땠습니까? | 감독 모델의 수용성 |
| C2 | 그 모델을 어디까지 확인해야 안심이 됩니까? | 검토 비용의 실제 크기 |
| C3 | 자동 생성된 추정치를 승인하려면 무엇이 보여야 합니까? | 신뢰 요건 |
| C4 | 본인 추정의 과거 정확도를 알고 계십니까? 알고 싶으십니까? | **§4 정확도 추적의 전제 검증** |

**C4가 가장 민감합니다.** 아플 수 있는 질문이라 조심스럽게 물어야 합니다. 답이 "알고 싶지 않다"면 정확도 추적 기능의 포지셔닝을 바꿔야 합니다 — 개인 성과가 아니라 **모델 품질 지표**로.

### D. 지불 의사 (15분)

| # | 질문 | 얻는 것 |
|---|---|---|
| D1 | 지금 회사가 돈 주고 사는 리서치 도구는 무엇입니까? | 실제 지출이 진짜 신호 |
| D2 | 개인 돈으로 사는 도구가 있습니까? | 개인 seat 가능성 |
| D3 | 도구 도입을 누가 결정합니까? | 구매자 식별 |
| D4 | (프로토타입 시연 후) 이게 있으면 무엇이 달라집니까? | 가치 검증 |

**D1이 D4보다 신뢰할 만합니다.** 가상 제품에 대한 지불 의사는 과대 보고됩니다.

### 인터뷰 대상 구성

| 대상 | 인원 | 왜 |
|---|---|---|
| 해외주식 담당 RA | 2~3 | 초기 타겟 |
| 국내주식 담당 RA | 2 | 대조군 |
| 애널리스트 (RA 보유) | 1~2 | 산출물 요구자 + 구매 영향력 |
| 리서치센터장 | 1 | **구매 결정권** |

센터장 인터뷰는 D3 답에 따라 우선순위가 달라집니다. 조직 구매가 확인되면 최우선입니다.

## 7. 인터뷰로 검증/기각할 가설

| # | 가설 | 기각 신호 | 기각 시 대응 |
|---|---|---|---|
| **H1** | 처리량 병목은 **모델 유지**다 | B1 답이 다른 것 (예: 산업 리서치, 미팅, 자료 수집) | 그것을 새 레버리지 포인트로 |
| H2 | 커버리지 확장 수요가 실재한다 | B3에서 "지금도 충분" | 커버리지 OS 방향 폐기, 심화 도구로 |
| H3 | RA는 감독자 역할을 수용한다 | C1~C3에서 강한 거부 | 생성 대신 검증 도구로 |
| H4 | 정확도 추적에 유인이 있다 | C4에서 회피 | 개인 지표 → 모델 품질 지표로 재포지셔닝 |
| H5 | 조직이 구매자다 | D3에서 개인 결정 | seat 기반 유지, 확장 가치 제안 축소 |

**H1이 무너지면 이 문서 전체를 다시 써야 합니다.** 그러니 B1을 가장 정성껏 물어야 합니다.

## 8. 인터뷰 전 준비물

| 준비물 | 목적 |
|---|---|
| SMIC 벤치마크 1건 (출력물) | "이런 수준의 리포트를 쓰는 데 얼마나 걸립니까?" 구체적 기준점 |
| 기존 Fact Layer 데모 (TSLA fixture) | D4용 최소 시연. **과대 약속 금지** |
| 시간 기록 템플릿 | A1 재구성용 |

시연은 **A·B·C를 다 물은 뒤**에 합니다. 먼저 보여주면 사용자가 제품 프레임 안에서만 답합니다.
