## 0. 먼저 — 법률 검토에 대한 내 판단을 정정한다

[09](09-what-the-interview-changes.md)에서 텔레그램 센티에 *"법률 검토 없이
손대면 안 된다"*고 썼다. **과했다.** 자본시장법이 규제하는 것은
**「대가를 받고 불특정 다수에게 투자 판단에 관한 자문을 제공하는 것」**
(유사투자자문업)이다. 우리가 하려는 것은 다르다:

| | 유사투자자문 | 우리 |
|---|---|---|
| 대상 | **불특정 다수** | RA 개인 (도구 사용자) |
| 산출 | **투자 판단·조언** | 「시장에서 이런 말이 돈다」는 **관측** |
| 성격 | 추천 | 정리 |

**「무슨 말이 돌고 있는지 요약해 준다」는 자문이 아니라 관측이다.** 그리고
그건 [D4](../decisions.md#d4)에서 **투자의견·목표주가를 애초에 안 낸다**고
정해 둔 것과 같은 선 위에 있다 — 우리는 원래 추천을 안 한다.

**PRISM-INSIGHT가 그 선례다.** 450명 이상에게 무료로 **텔레그램으로 종목
분석을 뿌리고**, 매매 시뮬레이션까지 공개하면서 디스클레이머 한 줄로 운영한다:
> *"Analysis information is for reference only, not investment advice."*

우리는 그보다 훨씬 보수적이다 — 추천도 목표주가도 안 낸다.

**그래도 남는 진짜 리스크는 셋인데, 법률이 아니라 실무다:**

1. **저작권** — 유료 채널의 내용을 **원문 그대로** 재배포하면 문제가 된다.
   → 요약하고 출처를 밝히면 된다. 우리는 이미 [D45](../decisions.md#d45)에서
   기사에 그렇게 하고 있다
2. **텔레그램 약관·계정** — 사용자 계정으로 자동 수집하면 정지될 수 있다.
   → **사용자가 내보낸 것을 올리는 방식**이면 피한다.
   [D48](../decisions.md#d48)의 업로드 경로가 그대로 쓰인다
3. **성격이 바뀌는 순간** — 요약을 **다수에게 파는** 서비스가 되면 그때는
   진짜 검토가 필요하다. **RA 개인 도구로 있는 동안은 아니다**

**결론**: 법률 검토를 3순위의 전제 조건으로 두지 않는다. **개인 도구 · 추천
없음 · 사용자 업로드**를 지키면 지금 만들어도 된다.

## 1. PRISM-INSIGHT는 무엇인가

| | |
|---|---|
| 성격 | **완전 오픈소스**(AGPL-3.0, 상업 SaaS는 별도 라이선스) |
| 대상 | **개인 투자자** |
| 하는 일 | 급등주 탐지 → 13+ 에이전트 분석 리포트 → 텔레그램 배포 → 매매 시뮬 → **실제 자동매매**(한국투자증권 API) |
| 규모 | 사용자 450명+, 운영비 **월 ~$310** (OpenAI $235 / Anthropic $11 / Firecrawl+Perplexity $35 / 서버 $30) |
| 실적 공개 | KR 시즌2: 86거래 · 승률 45.35% · **누적 +244.63%** — 다만 *"cumulative return is the sum of trade-level return rates … not a time-weighted portfolio return or a realizable backtest"*라고 **스스로 한계를 명시** |

### 에이전트 구성 (KR 리포트 6종 + 조합)

| 섹션 키 | 무엇을 보는가 |
|---|---|
| `price_volume_analysis` | 가격·거래량·기술적 구조 |
| `investor_trading_analysis` | **투자자별 수급** |
| `company_status` | 재무·사업 현황 |
| `company_overview` | 회사·제품·경쟁사 |
| `news_analysis` | 최근 뉴스·섹터 주도주·촉매 |
| `market_index_analysis` | KOSPI/KOSDAQ 시장 맥락 |

여기에 인라인으로 **투자전략 종합**과 **요약**이 붙고, 별도로 **매크로(시장
국면·섹터 로테이션·리스크 이벤트)**, **품질 평가**, **번역**, **매매 판단·저널**,
그리고 **텔레그램 상담 에이전트**가 있다.

### 데이터는 MCP로 붙인다

`kospi_kosdaq`(KRX) · `firecrawl`(웹 크롤링) · `perplexity`(웹 검색) ·
`sqlite`(시뮬 DB). 미국은 `yahoo-finance-mcp` · `sec-edgar-mcp`.

## 2. 우리와 무엇이 다른가 — 겹치지 않는다

| | PRISM-INSIGHT | ARC |
|---|---|---|
| **대상** | 개인 투자자 | **RA(리서치 어시스턴트)** |
| **목적** | 매매 판단 | 업무 산출물 |
| **투자의견** | 낸다 (매수/매도 실행까지) | **안 낸다** ([D4](../decisions.md#d4)) |
| **숫자의 출처** | 에이전트가 만든다 | **레지스트리를 거쳐 공시로 되짚는다** (불변식 1) |
| **검증** | 매매 성과로 사후 검증 | **발간 전 게이트**로 사전 차단 |
| **산출물** | 텔레그램 요약 · PDF | Word · Excel · Markdown (**넘기는 물건**) |

**핵심 차이 하나로 줄이면**: 저쪽은 **판단을 파는 것**이고 우리는
**판단의 재료를 검증해 넘기는 것**이다. 그래서 저쪽은 승률로 증명하고,
우리는 출처로 증명한다.

**그리고 그게 RA에게 필요한 것이다.** 인터뷰에서 확인됐다 — RA의 산출물은
클라이언트에게 청구되는 자료이고, *"오픈 소스를 믿지 못하겠는"* 것을 대신
정리해 주는 게 값이다. 틀리면 청구가 안 된다.

## 3. 배울 것 넷 (그대로 가져올 것)

### ① 섹션을 에이전트로 쪼갠다

우리는 LLM 호출이 사실상 셋이다(본문 서술 · 산업 배경 · 최근 이슈). 저쪽은
**섹션마다 전담 에이전트 + 전용 데이터 소스**다. 특히 우리에게 없는 둘:

- **`investor_trading_analysis` (투자자별 수급)** — 인터뷰에서 클라이언트
  리퀘스트의 대표 예가 *"신용잔고, 신용매수, 신용매도 종목별로 뽑아서
  보내줄래요"*였다. **수급은 우리가 아예 안 다루는 축이고, 요청이 실제로 온다**
- **`market_index_analysis` (시장 맥락)** — 인터뷰: *"섹터보다 더 하이어 단에서
  한국 증시 전체에 대한 뷰가 요즘은 필요한 시기"*

### ② MCP로 데이터 소스를 붙인다

우리는 어댑터를 직접 짠다(DART·KRX·네이버). 저쪽은 MCP 서버를 꽂는다. **새
소스를 붙이는 비용이 다르다.** 우리가 앞으로 붙일 것(퀀티와이즈·에프앤가이드·
수급 데이터)을 생각하면 이 구조가 유리하다.

### ③ 운영비를 공개한다

월 $310으로 450명. **우리 건당 비용이 $0.005**니까 자릿수가 맞는다 —
가격을 정할 때 근거가 된다.

### ④ 한계를 스스로 적는다

누적 +244%를 내면서 *"이건 시간가중 수익률도 실현 가능한 백테스트도 아니다"*
라고 같은 표에 적어 둔다. 우리가 [D34](../decisions.md#d34)에서 추정 오차를
공개한 것과 같은 태도다. **이런 제품에서 신뢰는 성과가 아니라 한계를 말하는
방식에서 온다.**

## 4. 그래서 만들 것 — 「RA 개인용」으로 다시 세운다

인터뷰가 준 답과 이 참고를 합치면 제품이 이렇게 정리된다.

> **RA 개인이, 자기 PC에서, 커버 밖 종목과 시장의 말을 정리하고,
> 클라이언트 질문에 답할 재료를 만드는 도구.**

세 축이고, 셋 다 **이미 만든 것 위에** 선다.

### 축 1 — 커버 밖 피어 뷰 (1순위, [09](09-what-the-interview-changes.md))

섹터를 지정하면 동일 섹터 N종목을 한 표로, 정기 업데이트. 지금 없는 것은
**여러 종목을 한 뷰로**뿐이고 나머지는 다 있다.

### 축 2 — 리서치 전용 채팅 (새로 — 인터뷰의 가장 큰 발견)

> *"리포트 쓰는 시간보다 훨씬 많은 비중은 클라이언트 리퀘스트"* — 하루 10~15건

**일반 챗봇이 아니다.** RA의 리퀘스트는 성격이 정해져 있다:

- *"신용잔고·신용매수·신용매도 종목별로 뽑아 줘"* → **정형 데이터 추출**
- *"오늘 ○○ 왜 떨어져요?"* → **뉴스·수급·공시 대조**
- *"중국이 10척 발주했는데 한국 조선소보다 얼마나 빨리 만들어요?"* →
  애널리스트 암묵지 (**우리가 못 한다. 못 한다고 말해야 한다**)

**그래서 이 채팅의 설계 원칙은 「모르면 모른다고 한다」다.** 우리 게이트가
이미 그 원칙 위에 서 있다 — 답을 지어내면 청구가 안 되고, 한 번 틀리면
다음부터 안 쓴다.

그리고 **답의 재료는 카드다.** 대화가 허공에서 답하는 게 아니라, 이미 검산된
카드·수치·출처를 근거로 답하고 **출처를 함께 낸다**. 그게 범용 챗봇과
갈라지는 자리다.

### 축 3 — 시장 센티 (텔레그램)

> *"압도적으로 중요"* · *"안 보면 국내 주식시장을 이해할 수 없어요"*

**사용자가 내보낸 것을 올리면 정리한다.** 자동 수집이 아니라 업로드다 —
계정 리스크를 피하고, [D48](../decisions.md#d48)의 변환 경로가 그대로 쓰인다.
숫자는 [D45](../decisions.md#d45)의 미검증 레인 규칙을 그대로 적용한다.
