### D8 — 제품 구조: 공통 엔진 + 표면 2개, 발간 먼저

> ⚠️ **2026-08-05 — [D38](#d38)로 대체됨.** 공통 엔진과 표면 2개 구조는 그대로 유효하다.
> **뒤집힌 것은 "발간 먼저" 하나**다. D8이 검토한 선택지에 *개인 셀프서브 RA 도구*가 없었기 때문이다.

**결정**: 데이터·계산·게이트·서술을 **하나의 엔진**으로 짓고, 그 위에 표면을 둘 올린다. **발간 표면을 먼저** 만든다.

```
                 ┌─────────────────────────────┐
                 │  공통 엔진                   │
                 │  데이터 · 계산 · 게이트 · 서술 │
                 └──────────┬──────────────────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
    ┌───────────────────┐      ┌────────────────────┐
    │ 발간 표면 (지금)    │      │ RA 도구 표면 (보류)  │
    │ 세미오토 자체 발간  │      │ 증권사 내부 도구     │
    │ 무료·일방향        │      │ 유료 seat          │
    │ 인허가 제로        │      │ 영업 필요           │
    └───────────────────┘      └────────────────────┘
```

**근거**:
1. 발간은 **인허가 제로로 당장 시작 가능**하고 유통 경로가 필요 없다 (D5)
2. 7/25 판단 그대로 — *"(b)로 시작하면 발간 실적·골든셋·검증 파이프라인이 자산으로 축적 → 이후 (a) B2B·증권사 제휴·유료화 어느 쪽으로든 전환 가능한 옵션 보존"*
3. [research/02-report-quality.md](research/02-report-quality.md) §3의 **추정 정확도 추적**이 자체 발간에서도 그대로 축적된다. 내 추정 vs 실제 실적 이력이 곧 B2B 전환 시의 신뢰 자산이다
4. RA 인터뷰를 발간 경험을 갖고 가면 질문의 밀도가 다르다

**보류 처리**: RA 도구 표면의 v0 설계는 [surfaces/ra-tool-v0/](surfaces/ra-tool-v0/)에 보존. [research/04-reshape-interview.md](research/04-reshape-interview.md) §7의 가설 H1이 인터뷰로 검증되면 되살린다.

<a id="d9"></a>
### D9 — 목표주가: 엔진은 계산하고, 표면이 정책을 정한다

**충돌이었던 것**: D4는 "단일 목표주가 출력 금지"인데, [research/03-valuation-boundary.md](research/03-valuation-boundary.md)는 "밸류에이션 계산까지 포기한 것은 과잉"이라 결론.

**해소**: 두 층을 분리한다.

| 층 | 정책 |
|---|---|
| **엔진** | 밸류에이션을 **계산한다** — 3표 전개, 멀티플 밴드, 분해 항등식, 시나리오, 교차검증. 모든 입력에 `source` 태그 (`estimate_model` / `human_assumption` / `sec_fact`) |
| **발간 표면** | 단일 목표주가·투자의견 **출력 차단** (D4 유지). 시나리오 3개 + 감도표 + 산식 공개만. G0가 강제 |
| RA 도구 표면 | 계산 제공 + 애널리스트가 명시적으로 채택. 자동 복사 금지 |

즉 **엔진의 능력과 표면의 정책이 다르다.** D4는 발간 표면의 정책으로 유지되고, 엔진은 계산을 온전히 제공한다.

검증된 세부: `PBR = PDR × ROE × 배당성향`은 근사가 아니라 **항등식**이다 (수치 검증 완료). 4개 중 3개를 넣으면 나머지가 결정되므로 정합성을 코드가 강제할 수 있다. 마진 브리지의 `reconciliation` 패턴과 같은 성질.

### D11 — 골든셋 출발점: SMIC 15건 + 선택 효과 보정

7/25가 *"한국어 리포트 품질 벤치마크는 전무하므로 골든셋 자체가 이 프로젝트의 핵심 데이터 자산"*이라 했다. 그 공백의 첫 채움으로 SMIC(서울대 투자 학회) 리포트 15건 분석을 확보했다 ([research/01-benchmark-smic.md](research/01-benchmark-smic.md)).

**다만 그대로 규범으로 쓰면 안 된다.** SMIC는 학회라 **쓰고 싶은 종목을 골라서** 쓴다. 배정 커버리지가 아니다:

| 지표 | 시장 (sell-side) | SMIC 15건 | 해석 |
|---|---|---|---|
| 매수 비중 | 93.1% | 100% | **선택 효과** — 편향이 아님 |
| 내재 상승여력 | 31% | 109.0% | 선택 효과 + 소형주 편중(10건 중 6건 시총 1조 미만). 잔여분 미확인 |

**채택 방식**: 구조는 학습하고 논조는 학습하지 않는다.

| 층 | 판단 |
|---|---|
| 구조 (추정 정밀도, 세그먼트 분해, P·Q 분해, 밸류에이션 논증 사슬, 부록 구성) | ✅ 골든셋으로 사용 |
| 논조·레지스터 (확신 표현, 상승여력 규모, rating 서술) | ❌ 제외 |

**결핍 확인**: 15건 전부가 확신에 찬 매수 아이디어라 **중립·부정 톤 참조가 없다.** 별도 코퍼스가 필요하다.

### D12 — 추정 정확도·revision 추적을 최우선 차별화로 승격

7/25가 이미 *"전 보고서 대비 추정 변화 추적 — 이것이 진짜 차별화"*라 했고, 템플릿 §5에도 반영돼 있다. 7/30~31 분석이 이를 **두 개의 독립 증거로 보강**했다:

| 증거 | 내용 |
|---|---|
| **FnGuide Best Analyst 루브릭** | 100점 중 **40점이 실적 추정 정확도** — 최대 단일 배점. 70%가 검증 가능한 예측 성과 |
| **SMIC 15건 계량** | `추정` 855회, `26E/27E/28E` **15/15건**. 컨센서스 인용은 5/15건뿐 (자체 추정이 표준) |
| 시장 실패 데이터 | 하향 조정이 상향보다 **72일 vs 61일** 지연. 신뢰가 무너지는 지점 |

**추가 결정 — 정합성 표시 3종** ([research/02-report-quality.md](research/02-report-quality.md) §3.5의 C안):

매수 편향 시장에서 rating에 개입하지 않고 **추정·목표주가·rating의 모순만 계산으로 드러낸다.**

| 표시 | 겨냥 |
|---|---|
| 목표주가 ↔ 추정 정합성 (괴리 %) | 근거 없는 목표주가 |
| **revision 정합성** ("추정은 하향, 목표주가는 무변동") | 72일 하향 지연 |
| 상대 대조 (내재 상승여력 vs 시장 평균 31%) | 낙관 편향 자각 |

**매도 의견을 유도하지 않는다.** 93.1% 매수는 발행사 관계·IB·법인영업에서 오는 제도 제약이고(외국계 지점은 같은 시장에서 15~22%), 도구가 고칠 수 없다. 도구는 계산만 하고 판단은 사람이 한다.

**구현 상태**: ✅ Number Registry + G0 구현 완료. 정합성 표시 3종은 미착수 — 추정 레이어가 선행되어야 한다.

### D3 보강 — 리포트는 재무제표에서 출발하지 않는다

SMIC 15건은 두 테마로 배타적으로 갈렸다: **AI 인프라 병목**(10건, `병목` 220회) / **밸류업·지배구조**(5건, `승계` 191회·`배당` 317회). 논리 흐름은:

```
매크로·정책 서사 → 산업 구조(밸류체인·병목) → 종목 선정 → 재무 추정 → 밸류에이션
```

재무 지표는 **논지의 증거**이지 출발점이 아니다. 실증: 손익계산서에서 앵글을 생성하면 NVDA FY2025(매출 폭증)와 TSLA(마진 하락)가 **글자까지 동일한 앵글 3개**를 받는다.

S2(재무분석 → thesis.json) 설계 시 반영할 것 — thesis는 산업·정책 입력을 받아야 한다.

### D14 — S4 서술 모델: GPT-5.6 Luna (최저가 티어)

**실측 근거** (2026-08-01, 삼성전자 FY2025, 5회 반복):

| 지표 | 결과 |
|---|---|
| G0 **1차 통과율** | **100%** (5/5) |
| 숫자 리터럴 유출 | **0%** |
| 카탈로그 밖 키 | 0% |
| 금지어(rating·단정) | 0% |
| JSON 파싱 실패 | 0% |
| 건당 비용 | **$0.0019** |
| 지연 | 9~12초 |

**가장 위험했던 가정이 검증됐다** — "LLM이 숫자 리터럴 없이 쓸 만한 한국어를
만들 수 있는가". 최저가 티어에서 1차 통과율 100%다.

이게 가능한 이유는 Number Registry가 LLM의 역할을 좁혀뒀기 때문이다. 계산도
검증도 하지 않고 정해진 어휘로 문장만 조립하므로, 플래그십이 필요한 작업이
아니다. 비용도 같은 이유로 무의미한 수준이다 — 100건/월에 $0.19.

설계서 추정($0.5~0.9/건)의 **1/300**이다. 추정 당시엔 S1 정규화·S2 분석·
S4 병렬 작성·S5 LLM 검증을 모두 LLM으로 가정했는데, 실제로는 S4만 LLM이고
나머지는 결정론 코드다.

**비용은 이 규모에서 제약이 아니다.** 플래그십(Sol)을 써도 100건/월 $3.45,
코스닥 전종목 분기 갱신도 월 $20 수준이다. 모델 선택은 비용이 아니라 품질로
한다. 다만 G1/G2 LLM 검증을 붙이거나 공시 원문을 프롬프트에 넣으면 이 계산은
깨진다.

<a id="d15"></a>
### D15 — 카탈로그에 방향(부호)을 포함한다

초판은 카탈로그에서 값을 완전히 뺐다. 그랬더니 LLM이 방향을 알 수 없어
모든 문장을 "변동했다"로 썼고, 지표를 하나씩 읊는 읽히지 않는 글이 나왔다.
[research/01-benchmark-smic.md](research/01-benchmark-smic.md) §3이 진단한
"손익계산서에서 출발하면 템플릿이 나온다"가 그대로 재현됐다.

**방향은 크기가 아니다.** 결정적 코드가 부호에서 뽑은 사실이므로 환각이 아니고,
크기는 여전히 노출되지 않는다. 카탈로그에 `direction`(증가/감소/보합)을 넣고
프롬프트에 "정도 표현(크게·소폭·급격히)은 금지"를 추가했다.

결과: 통과율 100%를 유지하면서 문장이 지표를 **연결**하기 시작했다
("원가 부담 완화가 총이익률 개선으로 연결", "영업단의 개선이 순이익단까지").

**남은 한계**: 여전히 산업·정책 서사가 없다. 프롬프트에 재무 카탈로그만 있어
LLM이 쓸 수 있는 것이 재무 기계학뿐이다. 세그먼트·공시 본문·산업 데이터가
붙어야 [research/01](research/01-benchmark-smic.md) §3이 말한 진짜 리포트가
된다. 이건 데이터 레이어 확장 과제이지 모델 문제가 아니다.

<a id="d16"></a>
### D16 — 논지는 결정적 코드가 만들고, LLM은 그것을 글로 만든다

[D15](#d15)가 남긴 한계("재무 기계학에서 멈춘다")의 원인을 다시 봤다. 카탈로그만
주면 LLM이 쓸 수 있는 게 **지표 목록**뿐이라, 문장이 지표를 하나씩 읊는다.
LLM에게 "논지를 세워라"라고 시키는 건 답이 아니다 — 논지를 세우려면 수치를
비교해야 하고, 우리는 의도적으로 수치를 안 보여준다.

그래서 **논지를 결정적으로 계산해 프롬프트에 넣는다**(`build_observations`).

- 마진 브리지: Δ영업이익률 = (−Δ원가율) + (−Δ판관비율). 근사가 아니라 **항등식**이다.
  삼성전자 FY2025 실측 잔차 0.000pp. 어느 비용이 마진을 움직였는지 확정된다.
- 외형 vs 이익 증가율 비교 → 운영 레버리지 작동 여부
- 영업이익과 순이익의 방향 불일치 → 영업외·법인세 요인 분리

**관찰문에는 크기를 쓰지 않는다.** 프롬프트에 들어간 숫자는 LLM이 리터럴로
베낀다. 방향과 우열(어느 쪽이 더 컸는가)만 담고 크기는 플레이스홀더로 본문에
들어간다. 이걸 회귀 테스트로 고정했다.

검산이 안 맞으면 지배 요인을 **말하지 않는다**. 영업이익 정의가 매출−원가−판관비와
다르다는 뜻이므로 단정하지 않고 그 사실을 서술한다.

결과: 투자포인트가 "매출은 X 변동했다"에서 "매출은 10.9% 증가했지만 영업이익은
33.2% 증가해 운영 레버리지가 작동했다"로 바뀌었다. 통과율 100% 유지.

### D17 — 검산값은 감사용이다 (`NumberEntry.internal`)

브리지 잔차를 카탈로그에 넣었더니 LLM이 본문에 "검산 차이는 +0.0pp로 확인된다"를
썼다. 맞는 말이지만 **독자용 문장이 아니다** — 내부 QA 값이다.

`internal=True` 항목은 카탈로그에서 빠지되 레지스트리에는 남는다. 치환·바인딩·
감사 추적은 그대로 되고 LLM만 못 본다. EPS 교차검증 괴리도 같은 처리.

<a id="d18"></a>
### D18 — 정기보고서 주요정보 API 계열을 쓴다

`~/Desktop/samil-hackathon`(사업보고서 3,293건 처리)을 보고 알았다.
`fnlttSinglAcntAll`(재무제표)과 **별개의 API 계열**이 있고, 12개 엔드포인트를
실제 키로 확인한 결과 전부 응답한다. 그중 4개를 붙였다.

| API | 얻는 것 | 왜 필요한가 |
|---|---|---|
| `stockTotqySttus` | 발행·자기·유통 주식수 | **밸류에이션의 분모.** 이게 없으면 시작조차 안 된다 |
| `alotMatter` | DPS·배당수익률·배당성향 | 배당 + **가격 앵커**(아래) |
| `accnutAdtorNmNdAdtOpinion` | 감사의견 + 핵심감사사항(KAM) | 리스크 섹션의 **외부 검증된** 근거 |
| `empSttus` | 부문별 인력 | 사업 구성 단서 |

**KAM이 특히 중요하다.** 감사인이 "여기가 위험하다"고 지목한 항목이라 우리
추측이 아니다. 컴플라이언스 부담 없이 리스크 서술의 근거로 쓸 수 있다. 다만
적정의견 하에서도 KAM은 항상 지정되므로 **부실 신호로 단정하지 않는다.**

실측이 잡아낸 함정 (전부 회귀 테스트로 고정)

- `isu_stock_totqy`는 **수권**주식수다. 쓰면 삼성전자 주식수가 3배가 된다.
  발행주식총수는 `istc_totqy`.
- `성별합계` 행이 DX·DS와 **함께** 온다. 부문으로 세면 총원이 정확히 2배.
- 자기주식 `-`는 미공시가 아니라 0이다. 발행 == 유통 항등식이 확정한다.
- KAM 구분자가 개행 없이 붙는다("…평가2. 재화의…"). 숫자·한글 순서를 둘 다
  쓰고 **순서대로 이어지는 마커만** 인정한다("제3자 배정"의 3을 오인하지 않게).
- `fo_bbm`이 사업부문이 아닐 수 있다. 셀트리온제약은 생산직·영업직 **직군**이다.
  이걸 사업부문으로 서술하면 리포트에 거짓이 들어간다 → `grouping`으로 분류.

**세그먼트에 대해**: DART에 부문별 **매출** API는 없음이 확정됐다. 부문별 인력은
얻었지만 인력 비중은 매출 비중이 아니다. 매출 세그먼트는 사업보고서 원문
파싱이 필요하고, 이는 [D13](#d13)의 우선순위 재검토 대상이다.

<a id="d19"></a>
### D19 — 시세 API 없이 밸류에이션을 시작한다 (역산 주가 앵커)

`KRX_API_KEY`가 없어 [D13](#d13)의 시세 연결이 막혀 있었다. 그런데 밸류에이션에
정말 필요한 건 주식수이고([D18](#d18)), 가격도 부분적으로 얻을 수 있다.

`alotMatter`가 **현금배당수익률**을 준다. DPS ÷ 배당수익률 = 주가다.

가격 없이 확정: BPS · ROE · ROA · 부채비율 · 배당수익률 · 배당성향
역산 앵커로: 주가 · 시가총액 · PER · PBR

**역산 주가는 특정일 종가가 아니다.** DART가 어느 시점 주가로 수익률을 계산했는지
명시하지 않는다(통상 배당기준일 전 일정 기간 종가 평균). 그래서 `is_implied`로
표시하고 라벨에 "역산"을 붙이고 리스크 섹션에 한계를 명시한다. 조용히 쓰면
독자가 종가로 오인한다. 시세 어댑터가 붙으면 대체한다.

**EPS 교차검증**: 재무제표 희석EPS vs 배당공시 (연결)주당순이익. 두 값은 **다른
경로**로 오므로 일치하면 주식수·순이익 기준이 양쪽 다 맞다는 뜻이다. 삼성전자
실측 괴리 −0.03%. 이게 주당 지표가 조용히 틀리는 걸 잡는 유일한 독립 검산이다.

기준을 섞지 않는 것이 핵심이다 — ROE·BPS는 **지배주주**, 부채비율은 **전체**,
시가총액 분모는 **발행**(유통 아님). 실제로 ROE 평균자본에서 당기는 지배주주,
전기는 전체를 쓰는 버그가 있었고 테스트가 잡았다.

### D20 — 커버리지가 다르면 낮은 쪽으로 폴백한다 (주요계정)

파마리서치(214450) FY2025는 사업보고서를 냈고 주요정보 API도 응답하는데
**전체계정(`fnlttSinglAcntAll`)만 013**이다. 두 API의 커버리지가 다르다.

`fnlttSinglAcnt`(주요계정)로 폴백한다. 계정이 30개뿐이라 매출원가·판관비가 없어
[D16](#d16)의 마진 브리지를 못 만들지만, 매출·영업이익·순이익·자산·부채·자본은
있다. **"발간 불가"와 "일부 지표 없음" 사이에서 후자를 택한다** — 코스닥 미커버
소형주가 타깃이므로 전자를 택하면 시장을 잃는다.

이 종목은 이전엔 아예 생성 실패였다. 지금은 지표 7개로 노트가 나오고, 못 찾은
계정은 한글 라벨로 본문에 밝힌다([D5](#d5) 원칙 유지).

주요계정은 형태도 다르다: `fs_div`를 줘도 CFS·OFS를 모두 돌려주고(안 거르면
자산총계가 두 개), `account_id`가 없고, 같은 계정이 중복으로 온다.

<a id="d21"></a>
### D21 — 같은 논지를 두 번 싣지 않는다 (리스크 병합)

[D16](#d16)으로 KAM을 논지로 주면 LLM이 그걸 리스크로 쓴다. 거기에 결정론
문장까지 붙이면 독자가 같은 말을 두 번 읽는다(실측으로 확인).

결정론 리스크에 주제 키워드를 달고, LLM 서술에 그 키워드가 이미 있으면 뺀다
(`merge_risks`). 결정론 쪽은 **누락 방지 안전망**이지 필수 문장이 아니다.

다만 범위 고지 두 줄(공시 밖 요인 미반영 / 추정 미구현)은 LLM이 뭘 쓰든 남긴다.

<a id="d22"></a>
### D22 — 장르는 실적 리뷰 노트다 (톤 결정)

사용자 지적: 출력이 "DART 사업보고서를 회계 펌이 쓴 것처럼" 읽힌다. 맞았고,
원인의 대부분이 이 저장소가 만든 것이었다.

원인 세 가지

1. **KAM을 본문에 인용했다** ([D18](#d18)의 오류). 실제 RA 리포트는
   핵심감사사항을 인용하지 않는다. "감사인이 ~을 지목했다"가 들어가는 순간
   회계법인 산출물처럼 읽힌다.
2. **"추가 확인이 필요하다" 어법.** 공시 밖 요인을 단정하지 말라는 프롬프트가
   실사 보고서 어투를 만들었다.
3. **방법론 고지가 리스크 섹션에 있었다.** "공시 기반 지표만 사용했다"는
   회사의 리스크가 아니라 우리 자료의 한계다.

수정

* KAM 취급을 가른다 — **비적정 의견·강조사항은 본문**(실제로 material),
  **적정의견 하의 KAM은 논지로만.** LLM이 사업 언어로 옮긴다
  ("수익인식 기간귀속" → "매출 인식 시점").
* 프롬프트 맨 앞에 장르 규정을 두고 두괄식을 요구. "추가 확인이 필요하다"를
  금지하고 "관건은 ~다", "~에서 갈린다"로 대체.
* '작성 기준' 섹션 신설 — 방법론 한계를 리스크에서 분리.

**구조적 원인과 그 해법**: 증권사 리포트의 목소리는 뷰에서 나온다.
[D4](#d4)로 목표주가·투자의견을 금지했으니 뷰가 빠진 자리에 "관측의 나열"만
남고, 그건 필연적으로 회계 문서가 된다.

목표주가는 계속 내지 않는다. 대신 **논지**를 낸다 — 규제 대상이 아니다.
'관전 포인트' 섹션을 추가했다: "무엇이 확인되면 판단이 달라지는가". 검증
가능해야 하고 "지속적인 모니터링이 필요하다" 같은 문장은 금지다.

사용자 문서(`what-makes-a-great-research-report.md` §2)가 말하는
*"the text ... **is** the informational content"*가 빠져 있었던 것이다.

<a id="d23"></a>
### D23 — 조사(助詞)는 치환 시점에 교정한다

LLM은 `{{num:...}}으로`라고 쓰지만 **치환될 값의 끝소리를 모른다.** 값을
안 보여주는 게 이 시스템의 전제([D15](#d15))라 알 수도 없다. 실측:

    40.0%으로 → 40.0%로     70.1%이 → 70.1%가
    53.2%을  → 53.2%를     44.2%과 → 44.2%와

단위가 조사를 결정하고 단위는 치환 시점에 확정되므로 **판단이 아니라
계산**이다. `render_text`가 치환하면서 고친다.

서술격조사는 건드리지 않는다 — "25.9%이며"는 받침이 없어도 원형이 표준이라
"25.9%며"로 고치면 오히려 나빠진다. 주격조사 `이`만 고친다.

<a id="d24"></a>
### D24 — 추정치는 가정의 함수다 (추정 레이어)

`what-makes-a-great-research-report.md` §1: FnGuide 배점의 **40점이 실적 추정
정확도**다. §4: 하향 조정이 상향보다 72일 늦는 것이 신뢰가 무너지는 지점이다.
추정은 리포트의 부속물이 아니라 평가 대상 그 자체이고, **초기 추정보다 수정
이력이 더 중요하다.**

지금까지의 원칙("확인된 것만 쓴다")과 충돌하지 않는다. 추정 레이어는 그
원칙의 **명시적 적용**이다:

* 모든 추정치는 가정에서 계산된다. 가정이 없으면 값도 없다.
* 가정은 전부 표시된다 — 값과 **근거**(`basis`)까지.
* 기본 가정은 과거 실적의 기계적 연장이고, 이건 예측이 아니라 **기준선**이다.
  그렇게 라벨링한다.
* 사람이 덮어쓰면 `is_override`로 구분되고 산출 방식이 "사용자 지정"으로 바뀐다.

**가정도 수치다.** 처음엔 가정을 문장에 리터럴로 썼고 G0가 바로 막았다.
가정 역시 레지스트리에 등록하고 플레이스홀더로 쓴다.

기계적 연장의 한계를 두 겹으로 막는다 — 성장률이 −50~100% 밖이면 산출하지
않고, 최근 성장률의 진폭이 20pp를 넘으면 경고를 단다. 사람이 명시적으로
지정하면 두 제한 모두 우회한다(판단의 주체가 다르다).

<a id="d25"></a>
### D25 — revision 이력은 발간일로 찍는다

추정 스냅샷의 시각을 실행 시각(wall clock)으로 찍으면 "그 시점에 무엇을
추정했는가"라는 point-in-time 질문에 답할 수 없고, 발간일 기준 as-of 조회가
어긋난다(실측으로 확인 — revision이 0건으로 나왔다).

`save_snapshot(snapshot_at=발간일)`로 찍고, 조회는 **이번 발간일 직전**으로
자른다(오늘 저장한 값을 다시 읽어 "변화 없음"이 되는 걸 막는다).

**게이트를 통과한 초안의 추정만 저장한다.** 차단된 초안의 추정이 다음 발간의
비교 기준이 되면 이력이 오염된다.

이것이 [D12](#d12)의 정합성 표시 3종이 서 있을 토대다. 실측 확인:
1차 발간 추정 7,704억원 → 가정 하향 후 2차 6,435억원, **하향 −16.5%**로
표에 잡힌다.

<a id="d26"></a>
### D26 — 화면은 서버 렌더로 먼저 세운다 (표면 v0) — [D37로 이관됨](#d37)

장기 계획은 Next.js + FastAPI다(ARCHITECTURE.md). 다만 이 화면의 목적은
**검토 흐름을 눈으로 확인하는 것**이지 프론트엔드 아키텍처 검증이 아니다.
서버 렌더(FastAPI + Jinja2)로 먼저 세우고, 같은 프로세스에 `/api/reports`를
열어 둔다 — Next.js가 나중에 그대로 호출하므로 버리는 코드가 아니다.

화면이 증명해야 하는 것은 셋이고, 셋 다 엔진이 이미 갖고 있는 성질이다:

1. **숫자를 클릭하면 출처가 나온다.** Number Registry가 없으면 불가능하고,
   이게 ChatGPT 대비 유일한 구조적 차별점이다.
2. **게이트가 보인다.** 통과/차단과 위반 내역이 화면에 있어야 "사람이 검토
   후 발간"이 성립한다. **차단된 초안은 본문을 렌더하지 않는다** — 보여주면
   검토자가 결과로 착각한다.
3. **가정을 바꾸면 추정이 바뀐다.** [D24](#d24)를 조작으로 보여준다.

이를 위해 `render/html.py`를 별도로 뒀다. CLI의 `render_text()`는 평문이라
출처가 사라진다. HTML 경로는 값을 `<span data-key data-formula data-doc …>`로
감싸되 **같은 레지스트리·같은 조사 교정**([D23](#d23))을 쓴다 — 화면과 파일의
숫자가 갈라질 수 없다.

부수 발견: `dart_reports.py`가 `Provenance`에 없는 `document_id=`를 넘기고
있었고 pydantic이 조용히 버렸다. 화면에 출처를 붙이려다 드러났다 —
**표면을 만들면 데이터 레이어의 구멍이 보인다.**

<a id="d27"></a>
### D27 — 생성과 발간은 다르다 ([D25](#d25) 수정)

D25는 추정 이력 조회 경계를 "발간일 **직전**"으로 잡았다. 자기 자신과
비교하는 걸 막기 위해서였는데, 그 전제가 "생성할 때마다 저장한다"였다.

화면을 만들면서 그 전제가 틀렸음이 드러났다. 생성할 때마다 저장하면 **가정을
만지작거린 흔적이 전부 "직전 추정"이 되어 이력이 무의미해진다.** 그리고 같은
날 발간 후 가정을 고쳐 다시 생성하면 변화가 보이지 않는다(실측).

바로잡은 모델:

* **생성** = 미리보기. 이력에 남지 않는다.
* **발간** = 검토 완료 선언. 이때만 추정을 스냅샷으로 저장하고 노트를 파일로
  쓴다. [D25](#d25)의 "게이트 통과분만 저장" 원칙은 그대로다.

저장이 발간에서만 일어나므로 조회 경계를 **발간일 끝(포함)**으로 되돌릴 수
있다. `build_report`는 저장보다 먼저 끝나므로 자기 비교 위험이 없다.

이건 기술 결정이 아니라 제품 결정이다 — "사람이 검토 후 발간"이라는 전제가
화면에서 두 개의 버튼으로 나타난 것이다.

<a id="d28"></a>
### D28 — 부문별 매출은 원문에서 뽑되, **매출액으로 검산해서만** 쓴다

[D18](#d18)에서 DART에 부문별 매출 API가 없음이 확정됐다. 남은 경로는
사업보고서 원문 「II. 사업의 내용 → 4. 매출 및 수주상황」의 표뿐이다.
`/api/document.xml`은 ZIP을 주고, 그 안 5~8MB XML에 DART 고유 표 태그가 있다.

원문 파싱은 API보다 훨씬 깨지기 쉽다. 회사마다 표가 다르다(실측):

| 회사 | 라벨 열 구조 |
|---|---|
| 파마리서치 | 구분 \| 판매구분 \| 금액 \| 비율 |
| 삼성전자 | 품목 \| 금액 |
| SK하이닉스 | 사업부문 \| 매출유형 \| 품목 \| 금액 |
| 셀트리온제약 | 사업부문 \| 매출유형 \| 품목 \| 판매구분 \| 금액 |

그래서 **파싱 결과를 믿지 않는다.** 부문 매출의 합은 손익계산서 매출액과
같아야 하고, 이 항등식이 파서를 외부에서 검증한다:

    Σ(부문 매출) ≈ 매출액   그리고   Σ(비중) ≈ 100%

[D16](#d16)의 마진 브리지와 같은 원리다. **검산이 닫히지 않으면 표시하지
않는다** — 잘못 읽은 부문 구성이 리포트에 실리면 되돌릴 수 없다.

구조는 고정 위치를 가정하지 않고 데이터에서 추론한다. 라벨 열 개수는 다수
행이 동의하는 위치로, 판매구분 열은 **내수·수출이 실제로 있는** 열로 정한다
(소계만 보고 고르면 전체 합계 행 하나 때문에 부문명 열이 잡힌다).

가장 어려웠던 것은 **중첩 소계**다. 셀트리온제약은 품목별 합계와 유형별
소계가 한 표에 함께 실려 있어 다 더하면 매출액의 1.77배가 된다. 계층 레벨별
후보를 만들어(레벨 L보다 깊은 라벨이 전부 비었거나 소계인 행만) 검산이
통과하는 것을 고른다. `제품소계` 같은 표기 때문에 소계 판정은 부분 일치다.

실측 4종목 전부 ±0.00%로 닫혔다. 부문이 하나여도 쓴다 — "반도체 단일"은
그 자체로 리포트에 실릴 사실이다.

**남은 한계**: 이 표는 제품·품목 기준이라 회계기준서상 영업부문(주석)과
다를 수 있다. 부문별 **이익**은 여전히 없다.

### D29 — 리포트가 손익계산서에서 출발하지 않는다 (사업 이해 레이어)

벤치마크(SMIC 15건, 29~36쪽)와 우리 노트(2쪽)의 갭을 좁히려다 원인에 닿았다.
분량은 결과이고 원인은 **회사가 무엇을 하는 회사인지 몰랐다는 것**이다.
[research/01](research/01-benchmark-smic.md) §3이 "리포트는 손익계산서에서
출발하지 않는다"고 진단했는데, 우리는 계속 거기서 출발하고 있었다.

재료는 이미 공시에 있었다. 「II. 사업의 내용 → 1. 사업의 개요」에 회사가 직접
쓴 사업 서술이 6,714자 있는데 한 글자도 안 읽고 있었다.

새로 읽는 것

| 소스 | 얻는 것 |
|---|---|
| 「1. 사업의 개요」 | 제품·핵심기술·자회사·해외전략 |
| 「2. 주요 제품 및 서비스」 | **3개년** 부문별 매출 (「4. 매출 및 수주상황」보다 표가 단순하고 연도가 나란히 있다) |
| `hyslrSttus` | 최대주주·특수관계인 지분율 |
| `otrCprInvstmntSttus` | 경영참여 출자처 |

**숫자 불변식은 그대로다.** 원문에는 등록되지 않은 숫자가 가득해서 그대로
넣으면 LLM이 리터럴로 베낀다. `mask_numbers()`로 가리되 **탐지와 같은
화이트리스트**를 쓴다 — 두 규칙이 갈라지면 "가렸는데 게이트에 걸리는" 상황이
생긴다. 연도는 남긴다(사실이고 게이트도 허용한다).

즉 LLM이 받는 것은 **질적 사실**(무엇을 파는가·어떤 기술인가·어디에 파는가)
이고 크기는 여전히 레지스트리만 안다.

게이트가 두 번 잡았다: 자회사 지분율을 표에 리터럴로 넣었다가 차단됐고(→
레지스트리 경유), 계층 제목 `### 2.1`의 2.1이 소수로 잡혔다(→ 화이트리스트에
계층 번호 추가. 본문의 2.1은 여전히 막힌다).

**지주형 판정은 건수가 아니라 비중으로.** 경영참여 12건이라고 지주사가 아니다.
파마리서치는 출자 장부가가 자산의 10.3%뿐인 사업회사이고 소액 투자조합이
건수를 부풀린다. 자산의 절반 이상이 묶여야 밸류에이션 방법이 달라진다.

<a id="d30"></a>
### D30 — 투자포인트는 논증이다 (반론이 없으면 소개다)

벤치마크의 투자포인트는 제목이 주장이고 5쪽에 걸쳐 논증한다. 우리는 3~5문장
관찰이었다. 프롬프트에 네 요소를 순서로 강제했다:

**주장**(두괄식) → **근거**(수치) → **반론**("다만 ~라면 이 해석은 성립하지
않는다") → **확인 지점**(다음 공시에서 볼 것)

반론이 핵심이다. 반론 없는 투자포인트는 주장이 아니라 소개다. 그리고 반론을
쓰려면 자기 논지가 어디서 깨지는지 알아야 해서, 논지 자체가 단단해진다.

제목도 라벨이 아니라 주장이어야 한다 — "수익성 개선"(무엇을 주장하는지 없음)이
아니라 "이익률 개선은 원가에서 왔고, 재현 가능성이 관건이다".

<a id="d31"></a>
### D31 — 미검증 레인을 허용하는 조건은 "숫자가 없을 것"

벤치마크의 1~2장은 매크로·정책·산업 서사인데 공시에 없다. 사용자 결정으로
**별도 미검증 레인**을 열되 표시한다: 「0. 산업 배경」 + ⚠ 배지 + 작성 기준 명시.

이 레인을 허용할 수 있는 이유는 하나다 — **숫자가 없기 때문이다.**

* 수치 카탈로그를 주지 않는다.
* **두 번째 LLM 호출로 분리한다.** 같은 호출에 섞으면 재무 서술로 변질된다.
* 숫자가 하나라도 있으면 **문단만 버린다.** 리포트 전체를 막지 않는 이유는,
  검증 불가능한 레인 하나 때문에 검증된 나머지를 못 내보내는 게 합리적이지
  않아서다.

**다른 섹션보다 엄격하다.** G0 화이트리스트는 연도를 허용하지만 이 레인에서는
연도도 막는다 — "2025년부터 규제가 바뀌었다"는 아무도 확인할 수 없다.
테스트가 이걸 잡아서 알았다.

부수: LLM이 부문 매출 비중을 말하며 "비중 확대"를 썼는데 이건 투자의견
(overweight)이라 문맥과 무관하게 차단된다. [D22](#d22)와 같은 처방 — 본문에서
rating 어휘를 아예 안 쓰게 했다.

<a id="d32"></a>
### D32 — 차트는 수치의 두 번째 출처가 되면 안 된다

SVG `<text>`는 G0 스캔 대상이 아니다. 차트에 값 라벨을 넣으면 **게이트 밖에서
수치가 생긴다.** 그래서 형태로 비교만 보여주고 정확한 값은 바로 위 표에 둔다.
차트가 두 번째 출처가 되면 표와 갈라질 수 있고, 갈라져도 아무도 못 잡는다.

외부 차트 라이브러리를 쓰지 않는 이유: 웹은 인라인 정책을 전제로 만들었고
마크다운 산출물은 파일 하나로 완결돼야 한다. 순수 SVG 문자열이면 양쪽 다 된다.

<a id="d33"></a>
### D33 — 부문별 이익은 주석에서 뽑고, **총계 열로** 검산한다

[D28](#d28)로 부문별 **매출**은 얻었지만 정작 애널리스트가 묻는 질문에는
답하지 못했다: **어느 부문이 돈을 버는가.** 기업회계기준서 제1108호가
보고부문별 손익을 주석으로 요구하고, `<TE>` 셀 파싱이 열리면서 거기 닿았다.

표가 매출 표와 **전치**돼 있다 — 행이 계정, 열이 부문이다. 그래서 D28의
파서를 쓸 수 없다. 제목도 갈린다: 「부문별 보고」·「부문별정보」·「영업부문」·
「영업부문 정보」·「부문정보」.

**검산 방식이 D28과 다르다.** D28은 Σ(부문) = 매출액을 요구했는데, 부문
주석에서는 이걸 요구하면 **정상 공시를 거부한다**:

| 회사 | Σ(부문 매출) ÷ 연결 매출액 |
|---|---|
| LG전자 | 1.00 |
| 롯데케미칼 | 1.08 |
| 삼성전자 | 1.09 |
| CJ제일제당 | 1.35 |

부문 매출에는 내부거래가 남아 있고 별도 표시하지 않는 「기타」가 있다.
대신 주석 자신이 주는 **기업 전체 총계 열**을 쓴다:

    총계 열의 매출액   ≈ 손익계산서 매출액
    총계 열의 영업이익 ≈ 손익계산서 영업이익      ← 둘 다, **같은 열**에서

두 값은 완전히 다른 경로로 온다(원문 표 파싱 vs `fnlttSinglAcntAll` API).
서로 무관한 두 값이 같은 열에서 동시에 맞을 확률은 무시할 수 있으므로, 이
하나가 행·열·단위를 전부 검증한다. 실측: 삼성전자·LG전자·CJ제일제당은
**자릿수까지 일치**, 롯데케미칼은 18.5조에 78원(반올림) 차.

부수적으로 얻은 것: 단위를 캡션에서 못 읽어도 된다. 검산이 통과하는 배율을
고르면 되고, 그게 캡션보다 강한 근거다.

**섹션도 검산이 고른다.** 같은 보고서에 연결과 별도 주석이 함께 실린다.
제목으로는 가릴 수 없으니 후보를 전부 넘기고 총계가 맞는 것을 쓴다 —
연결 분석에 별도 주석이 섞이는 경로가 여기서 막힌다.

실측 결과

| 회사 | 결과 |
|---|---|
| 삼성전자 | DX·DS·SDC·Harman. **매출 1위 DX(6.8%), 이익 1위 DS(19.1%)** |
| LG전자 | 6개 부문, MS가 영업적자 |
| 롯데케미칼 | 4개 부문, 2개 적자, 단위 천원 |
| CJ제일제당 | 식품·바이오·물류 |
| SK하이닉스·파마리서치·셀트리온제약 | 단일 부문 — 주석 없음. **정확히 거부됨** |

리포트가 답할 수 있게 된 것

* 매출 1위와 이익 1위가 **다르면** 그것 자체가 투자포인트다. 전사 지표에는
  이 사실이 아예 나타나지 않는다.
* 부문별 이익률의 **방향이 갈리면** 전사 마진 변화를 전사 공통 요인으로
  설명할 수 없다.

**전사를 끌고 간 부문은 이익률 변동 폭이 아니라 이익 변화액으로 가른다.**
LG전자 기타부문은 이익률이 10.8pp 흔들렸지만 매출 비중이 2.4%라 전사에는
거의 영향이 없다. 실제 주범은 MS(-1.0조)다. [D28](#d28)의 기여도 판정과
같은 이유이고, 처음엔 여기서 틀렸다.

**적자가 섞이면 이익 비중을 내지 않는다.** 분모가 작아지거나 부호가 뒤집혀
"이 부문이 이익의 105%"가 나온다. 매출 비중만 낸다.

부수 결함(게이트가 잡음): 롯데케미칼 출자 현황의 법인명에 각주 표시가 붙어
온다(`LOTTE Chemical Titan Holding Berhad (*6)`). 본문 표에 그대로 실려 G0가
발간을 막았고, **그건 옳은 판정이다** — 레지스트리에 없고 뜻을 보장할 수 없는
숫자다. 게이트를 푸는 대신 이름에서 각주를 뗐다.

**남은 한계**: 부문별 자산·설비투자는 아직 읽지 않는다. 부문 ROIC을 내려면
필요하다.

### D34 — 기준선의 성적을 재고 공개한다 (백테스트)

[D12](#d12)는 추정 정확도를 최우선 차별화로 올렸고 [D24](#d24)는 추정 레이어를
지었는데, 정작 **우리 기준선의 성적은 몰랐다.** 선언과 실측 사이의 빈칸이다.
`finmodel/backtest.py` · `arc backtest`.

**시점 정합성이 전부다.** FY(Y+1)의 정보가 한 톨이라도 섞이면 백테스트는 좋은
숫자를 내면서 거짓말을 한다. 두 방향을 코드가 막는다: 추정은 FY(Y) 보고서만으로
만들고(그 안에 FY(Y-1)·FY(Y-2)가 비교표시로 있다), 실적은 FY(Y+1) 보고서의
**당기** 값을 쓴다(뒤 보고서의 비교표시는 재작성이 반영돼 다른 질문에 답한다).

측정 결과 — 활동 중인 코스닥 100곳 × FY2021~2024 (n=337)

| | 오차 중앙값 | 편향 중앙값 | ±20% 내 | 매출 대비 | 흑/적 방향 | 폭발(>100%) |
|---|---|---|---|---|---|---|
| 매출액 | **18.5%** | +6.5% | 53% | — | 100% | 5% |
| 영업이익 | 55.9% | +6.8% | 23% | **4.7%p** | 81% | 33% |
| 당기순이익 | 66.4% | +10.8% | 19% | 5.6%p | 81% | 36% |

커버리지: 400쌍 중 363쌍(91%)이 대조 가능, 그중 337건(93%)에서 추정을 냈다.

**읽는 법**: 매출 기준선은 참고용으로 쓸 만하다(절반이 ±20% 안). **이익
기준선은 그렇지 않다** — 매출의 4.7%p를 빗맞히고, 5곳 중 1곳은 흑자·적자
방향조차 틀린다. [D24](#d24)가 "예측이 아니라 출발점"이라 라벨링한 것이
과한 겸손이 아니었다.

측정이 바로잡은 것 셋

1. **평균을 대표값으로 쓰면 안 된다.** 첫 집계에서 매출 편향이 +118%로 나왔는데
   +20,852% 한 건이 만든 값이었고 중앙값은 +6.6%였다. 같은 표본에서 "두 배 넘게
   과대추정한다"와 "7% 위로 기운다"가 갈린다. 중앙값을 앞세우고 평균은 보관만 한다.
2. **이익 오차는 매출로 나눠 읽어야 한다.** 영업이익 5,700만원인 회사에 −63억을
   추정하면 −11,204%다. 크다는 것 말고 읽을 게 없다. [D33](#d33)에서 부문 손익을
   검산할 때 쓴 척도와 같은 이유다.
3. **표본이 답을 만들었다.** corpCode 인덱스에는 **상장폐지된 회사가 남아 있다**
   (stock_code가 유지된다). 무작위로 뽑으니 절반이 텔슨정보통신·코오롱유화 같은
   폐지 종목이었고 "데이터 커버리지 47%"가 나왔다. 직전 사업연도 재무제표가
   나오는 곳으로 좁히니 **91%**다. 앞의 숫자는 우리 파이프라인의 성질이 아니라
   표본의 성질이었다.

**산출 거부는 오차가 아니다.** 성장률이 −50~100% 밖이면 추정을 내지 않는데
([D24](#d24)) 이걸 오차 0으로 세면 성적이 좋아 보이고, 무한대로 세면 나빠 보인다.
따로 세고 커버리지로 보고한다.

**한계**: 직전 사업연도 공시로 표본을 좁혔으므로 기간 중 사라진 회사가 빠진
**생존 편향**이 있다. 숨기지 않는다.

이 숫자를 리포트에 싣는 것은 다음 단계다 — [D12](#d12)의 정합성 표시 3종이
설 자리이고, "우리 기준선의 과거 오차는 이만큼"이라고 밝히는 것이 그 자체로
차별화다.

<a id="d33-2"></a>
### D33 보강 — 부문 감가상각·자산 (Q12 해소)

[D33](#d33)이 연 표에 감가상각비가 함께 있었다. **같은 격자의 다른 행이라 열
배치와 단위는 이미 검증돼 있다** — 비싼 검증은 표·열·단위 식별이고 그건
매출·영업이익 총계가 끝냈다. 그래서 추가 검산 없이 읽는다.

얻은 것: **부문 EBITDA 마진.** 실측 4사 전부 나온다.

| 삼성전자 | 영업이익률 | EBITDA 마진 | 상각 부담 |
|---|---|---|---|
| DX 부문 | 6.8% | 9.2% | 2.4pp |
| **DS 부문** | 19.1% | **48.9%** | **29.8pp** |

영업이익률만 보면 DS가 DX보다 세 배 남는 사업이지만, 상각 전으로는 다섯 배다.
**두 사업은 같은 종류의 수익성이 아니다.** 전사 지표는 물론 부문 영업이익률만
봐도 이 차이가 보이지 않는다.

부문 **자산**은 다른 표라 따로 검산한다(재무상태표 자산총계와 대조). 다만
검산 근거가 하나뿐이라(손익은 매출·영업이익 둘) 구조 조건으로 보강했다 —
**총계 열은 부문 열보다 뒤에 있어야 한다.** 이 조건이 없으면 자산총계와 우연히
가까운 부문 열 하나가 총계로 위장하고 그 왼쪽 몇 개만 부문으로 잡힌다(테스트가
잡았다).

공시 여부가 갈린다: LG전자·롯데케미칼은 있고, 삼성전자는 「보고부문별 자산과
부채는 경영위원회에 정기적으로 제공되지 않아 포함하지 않았습니다」라고 명시한다.
기준서가 CODM에게 정기 제공될 때만 요구하므로 **없는 게 결함이 아니다.**

두 가지를 실측이 바로잡았다:

* **부문명이 조정 열에서 되풀이돼** 빈 값이 부문 자산을 덮어썼다(롯데케미칼).
  합계 열에서 끊는다 — [D33](#d33)의 손익 파서와 같은 처방이다.
* **자산 표가 부문을 약칭으로 부른다**(LG전자: HS·MS·VS). 위치로 짜맞추지 않고
  손익 표의 「각 보고부문의 약칭」 행이 준 대응표를 쓴다. 짝이 없는 부문
  (「기타부문」 vs 「기타부문 및 내부거래」)은 그것만 비운다 — 전부 버리면
  나머지 다섯의 자산까지 잃는다.

잔여 버킷은 논지의 주어가 되지 않는다. LG전자 「기타부문」은 매출 비중 2.4%인데
상각 부담이 가장 무거워 1위로 잡혔다. 매출 비중 5% 미만은 이 문장에서 뺀다
([D33](#d33)의 기여도 판정과 같은 이유이고, **세 번째로 같은 함정을 밟았다**).

### D35 — View는 **인물이 아니라 렌즈**로 낸다

[D22](#d22)가 진단한 빈 곳이 남아 있었다 — 목표주가·투자의견을 금지했으니
뷰가 빠진 자리에 관측의 나열만 남는다. 「관전 포인트」를 만들었지만 얇았다.

제안된 안은 **실명 페르소나**였다: 버핏 주주서한을 읽혀 에이전트로 만들고,
애크먼도 그렇게 만들어 3~4개 관점의 variation을 준다. 계기는 홍콩 서비스
Edgen이었는데, 조사해 보니 **Edgen의 17개 에이전트는 기능별이지 페르소나가
아니다.** 그 패턴의 실제 출처는 `virattt/ai-hedge-fund`(GitHub 51.7k)이고,
스스로 proof-of-concept이라 밝힌 데모다 ([research/05](research/05-view-and-personas.md)).

**실명 페르소나는 채택하지 않는다.** 둘이 치명적이다:

* **D4와 정면 충돌** — "버핏이라면 샀을 것"은 우회가 아니라 투자의견 그 자체다.
* **실존 인물 사칭** — 살아 있는 실명 인물에게 하지 않은 말을 귀속시킨다.
  "조사분석자료가 아님" 면책은 명예훼손·퍼블리시티권과 무관하다.

덧붙여, 크기를 못 보는([불변식 1](#d15)) 페르소나는 말투만 남고, 정확도를 잴
수 없어 [D34](#d34)로 세운 "측정 가능성이 해자"와 모순된다.

**대신 렌즈를 쓴다.**

> 페르소나는 **결론**을 내지만, 렌즈는 **다른 질문**을 던진다.
> 같은 검증된 숫자에 서로 다른 질문을 던지고, **답이 갈리는 지점이 곧 View다.**

| 렌즈 | 질문 | 재료 |
|---|---|---|
| **자본수익률** | 투입 자본 대비 얼마를 버는가 | 부문 자산·ROA·EBITDA([D33 보강](#d33-2)) · ROE · 출자 장부가 |
| **재현성** | 이번 이익은 반복되는가 | 마진 브리지([D16](#d16)) · 부문별 이익률 방향 · 영업이익 vs 순이익 |

렌즈는 결정적 코드가 관찰문을 만들고 LLM은 글로만 옮긴다 — [D16](#d16)과 같은
패턴이라 불변식이 깨지지 않는다. 렌즈가 **질문**이지 **판정**이 아니므로 D4도
건드리지 않고, 렌즈 A의 결론이 렌즈 B의 반론이 되어 [D30](#d30)과 이어진다.

**렌즈가 갈리는 지점을 「관전 포인트」에 싣는다.** D22가 만들고 못 채운 섹션이
여기서 채워진다. 실측: 롯데케미칼은 자산가치로 보면 싸지만 자산 31.1조 중
24.0조가 영업적자 부문에 묶여 있다 — **"싸 보이는 이유가 자산이 안 벌기
때문"**이고, 전사 지표로는 나오지 않는 논지다.

버핏 주주서한은 그래도 읽는다. 다만 **이름을 산출물에 붙이지 않는 용도**다 —
뽑을 것은 그의 결론이 아니라 **어떤 질문을 먼저 던지는가**이고, 그게 렌즈
설계의 입력이 된다. [D11](#d11)이 SMIC에 적용한 원칙과 같다: 구조는 학습하고
논조는 학습하지 않는다.

**실패 조건을 미리 적는다.** 렌즈가 갈리는 회사가 거의 없다면 이 설계는
복잡성만 늘린 것이다. 그때는 접고 관전 포인트를 다른 방식으로 채운다.

<a id="d35-2"></a>
### D35 보강 — 뷰의 차이는 부호가 아니라 **순서와 다음에 볼 것**에서 온다

초판은 렌즈마다 `stance`를 하나 두고 "부정이 하나라도 있으면 부정"으로 접었다.
사용자 지적이 이걸 무너뜨렸다 — *"같은 긍정이라도 말하는 태도의 차이가 클 수
있다. 중요하게 보는 요소가 다르거나, 같더라도 우선순위나 평가하는 보조지표가
다르거나."*

**맞았고, 만든 것에서 바로 증거가 나왔다.** LG전자 자본수익률 렌즈의 주된
발견은 「자산이 흑자 부문에 배치돼 있다」(긍정)인데, 부차적인 레버리지 관찰
하나 때문에 렌즈 전체가 부정으로 접혀 **1순위 발견과 정반대 문장**이 관전
포인트에 실렸다. 만든 것은 렌즈가 아니라 부호 하나로 접히는 스위치였다.

세 축을 코드에 대응시켜 다시 짰다:

| 축 | 대응 |
|---|---|
| 무엇을 보는가 | 렌즈마다 다른 데이터 (초판에도 있었음) |
| **무엇을 먼저 보는가** | `chain` — 질문 사슬이 순서를 고정한다 |
| **다음에 무엇을 볼 것인가** | `watch` — 렌즈마다 다음 분기에 볼 숫자를 하나 지목한다 |

**우선순위는 임의가 아니라 질문에서 도출된다.** 자본수익률 렌즈의 사슬은
「자본이 어디에 놓여 있는가 → 그 자본이 버는가 → 지금 수익률이 무엇에서
오는가」이고, **1단계를 모르면 2단계를 말하지 않는다.** 임의로 매기면 그건
페르소나를 기각한 이유(근거 없는 판단)를 렌즈 이름으로 되풀이하는 것이다.

렌즈는 이제 부호로 접히지 않고 **주된 발견(headline) + 단서(caveat) + 다음에 볼
것(watch) + 답하지 못한 질문(unanswered)**으로 남는다. LG전자는 이제 이렇게 나온다:

> 자산이 대체로 흑자 부문에 배치돼 있다.
> **다만** — 자기자본이익률이 총자산이익률을 크게 웃돈다. 그 차이는 부채 사용에서 온다.

**충돌도 세 종류로 갈렸다:**

| 종류 | 언제 |
|---|---|
| `verdict` | 두 렌즈의 결론이 갈린다 (초판이 유일하게 잡던 것) |
| `grounds` | **결론은 같은데 볼 숫자가 다르다** |
| `caveat` | 한 렌즈 안에서 주된 발견과 뒤 판독의 방향이 갈린다 |

`grounds`가 특히 중요하다. 초판은 둘 다 긍정이면 **아무 말도 안 했는데, 그때가
독자를 가장 오도하기 쉽다** — "합의됐다"로 읽히지만 실제로는 서로 다른 방식으로
맞을 수 있다는 뜻이다.

**「답하지 못한 질문」도 출력한다.** 삼성전자는 부문 자산을 공시하지 않아
1순위 질문에 답하지 못한다. 그 사실 자체가 회사에 대한 정보다. 이걸 숨기면
"확인했는데 문제없다"로 읽힌다.

**부수 확인 — 페르소나 기각이 옳았다는 방증.** 사용자가 같은 저자의 후속
프로젝트 [`virattt/dexter`](https://github.com/virattt/dexter)를 짚어 줬는데,
**페르소나를 버리고 기능형 에이전트 + 작업 분해 + 자기검증으로 갔다.**
페르소나 프로젝트를 바이럴시킨 본인이 다음 것을 그렇게 짓지 않았다. 다만
Dexter는 README에 *"결과가 틀리거나 불완전할 수 있다"*고 명시하며 검증을
포기한다 — 우리는 그 문장을 쓸 수 없고, 그게 차이의 전부다.

Dexter에서 가져올 만한 것은 **작업 분해 자체를 산출물로 보여주는 것**이고,
`chain` + `unanswered`가 그 자리다. 우리 쪽이 더 강한데, 계획이 고정이라
**어느 질문에 답했고 어느 질문에 못 답했는지가 검증 가능**하기 때문이다.

### D35 보강 2 — 렌즈는 **타깃 시장의 데이터에서** 고른다

사용자 지적: *"작업이 안 되었는데 푸시가 무슨 소용이야."* 맞았다.

초판·2차 모두 **대형주 4곳**(삼성전자·LG전자·롯데케미칼·CJ제일제당)으로 검증하고
일반화했다. 타깃인 코스닥 25곳에서 재보니 참사였다:

| | 초판 |
|---|---|
| 자본수익률 렌즈가 요구하는 **부문 자산** | **0/25** |
| 그 렌즈가 낸 "결론" | 전부 3순위 관찰(ROE vs ROA) 하나 |
| 그 문장 | **다섯 곳이 글자까지 동일** |
| 관점 충돌 | **4/25 (16%)** |

[D3 보강](#d3-보강)이 이미 기록한 실패 모드(*"NVDA와 TSLA가 글자까지 동일한
앵글을 받는다"*)를 렌즈 이름으로 재현한 것이다.

**먼저 데이터를 재고 그 위에서 렌즈를 골랐다** (코스닥 22곳 실측):

    최대주주·ROE·사업개요 100% · 부문 매출 82% · 출자 장부가 73% · 다부문 64%
    마진 브리지 55% · 자기주식 50% · 배당성향 27% · 부문 자산 0%

내가 고른 두 렌즈가 하필 가장 희소한 데이터를 요구했다. 세 렌즈로 다시 짜되
**1순위 질문을 가용률 높은 것으로** 놓았다:

| 렌즈 | 1순위 질문 | 가용 |
|---|---|---|
| **자본** | 투입한 자본이 수익을 내는가 (ROE) | 100% |
| **집중** | 매출이 어디에 몰려 있는가 (부문 매출) | 82% |
| **재현성** | 무엇이 마진을 움직였는가 (브리지) | 55% |

**구조 규칙 하나가 상용구를 막는다: 1순위에 답하지 못하면 결론을 내지 못한다.**
뒤 단계 관찰은 맥락으로 남되 판정이 되지 않는다. 이 규칙이 없어서 "다섯 곳 같은
문장"이 나왔다.

**판독은 회사를 지목한다.** 부문명·출자처·최대주주 이름을 부르고, 크기는
`slots`으로 플레이스홀더가 물고 온다. 이름도 숫자도 없는 판독은 상용구다.

결과 (같은 코스닥 22곳)

| | 초판 | 2차 수정 |
|---|---|---|
| 자본 관련 렌즈 결론 | 실질 0% | **100%** |
| 집중 렌즈 결론 | — | 45% |
| 재현성 렌즈 결론 | 55% | 55% |
| **관점 충돌** | **16%** | **73%** |

파마리서치(타깃 시장 대표)가 **두 렌즈 침묵 → 자본·집중 모두 발화**로 바뀌었다.

실측이 두 결함을 더 잡았다:

* **D28 파서가 「제품」·「-」를 부문명으로 뽑는다.** 그대로 인용하니 "매출이
  제품에 몰려 있다"가 나왔다 — 아무 말도 아니다. 이름을 못 믿으면 사업 집중을
  말하지 않는다(집중 렌즈 결론이 82%→45%로 내려간 대가다. 정직한 쪽을 택했다).
* **이름 뒤 조사가 틀린다.** "화장품은 늘고 **기타은** 줄었다". [D23](#d23)의
  치환 시점 교정은 플레이스홀더 뒤만 고치므로, 결정적 코드가 이름을 넣을 때는
  `josa.attach()`로 받침을 보고 골라야 한다.

**교훈은 렌즈보다 크다.** 이 저장소는 4종목 회귀 세트로 검증해 왔는데 그중
셋이 대형주다. **타깃이 코스닥 미커버 소형주라면 검증도 거기서 해야 한다.**

### D36 — 출처는 **항목마다 다르고, 파일에도 남는다**

사용자 지적: *"RA 분들은 출처에 굉장히 민감할 것 같은데, 중간중간 출처를 표기하고
클릭 가능하게 해서 직접 검증할 수 있게 해야 하지 않나."*

[D26](#d26)으로 웹에서 숫자를 클릭하면 팝오버가 뜨긴 했다. 그런데 실측해 보니
**바인딩 47건이 전부 같은 출처 하나**를 가리켰다.

원인: 데이터 레이어에는 API별 provenance가 **이미 있는데** 파이프라인이 전부
`stmt.provenance`(재무제표)로 덮어쓰고 있었다. 배당성향은 `alotMatter`,
최대주주 지분은 `hyslrSttus`, 부문 매출은 **원문 표 파싱**에서 왔는데 전부
"재무제표"로 표시됐다. 검토자가 "이 배당성향 어디서 나왔죠?"라고 물으면 **틀린
답**을 하는 상태였고, 이건 제품의 핵심 주장을 갉아먹는다.

**고친 것 셋**

**① `source_url`과 `verify_url`을 나눈다.**
`https://opendart.fss.or.kr/api/alotMatter.json`은 키가 필요한 JSON이라
**검토자가 클릭해도 아무것도 안 나온다.** 재현에는 그 주소가, 검증에는 DART
뷰어가 필요하다. 한 필드에 뭉치면 둘 중 하나는 반드시 쓸모없어진다.
`dataset`(사람이 읽는 이름)도 함께 넣었다.

**② 파이프라인이 항목별 출처를 살려 넘긴다.** 배선 문제였다. 결과:

| | 이전 | 이후 |
|---|---|---|
| 서로 다른 출처 | **1종** | **6종** |

    19건  재무제표 (주요계정)
    12건  사업보고서 원문 · 주요 제품 및 서비스
     6건  추정 (기준선 · 과거 실적의 기계적 연장)
     5건  정기보고서 · 타법인 출자현황
     3건  정기보고서 · 배당에 관한 사항
     2건  정기보고서 · 최대주주 및 특수관계인 주식소유 현황

**추정치는 공시가 아니라 우리 계산**이라 따로 표시한다 — 원본 공시로 적으면
검토자가 DART에서 없는 것을 찾는다.

**③ 마크다운에 「11. 수치 출처」 표를 붙인다.**
웹에서만 검증되면 **파일로 받는 순간 출처가 사라진다.** 발간물이 파일인 이상
파일 안에 검증 경로가 있어야 한다. 항목 · 값 · 산식 · 출처 · 공시번호(링크).

값은 **플레이스홀더로 넣는다** — 본문과 같은 레지스트리를 거치므로 표와 본문의
숫자가 갈라질 수 없고 G0도 그대로 통과한다. 표가 본문의 일부라 "본문에 등장한
키"를 뽑는 데 순환이 생기므로 **두 번 렌더한다**(1차: 표 없이 → 키 추출,
2차: 표 채움).

**딥링크는 하지 않는다.** 뷰어의 특정 표로 가려면 `dcmNo`/`eleId`가 필요하고
별도 호출·파싱이라 깨지기 쉽다. 대신 **섹션 제목을 명시**한다 — 「사업보고서
원문 · 주요 제품 및 서비스」라고 적으면 검토자가 뷰어 좌측 트리에서 바로 간다.

실측이 잡은 것들

* **G0가 URL과 접수번호를 막았다.** 옳은 판정이라 게이트를 푸는 대신 **좁게**
  넓혔다 — URL 안의 숫자(주장이 아니라 주소)와 14자리 접수번호(금액이면 콤마가
  붙는다). 그 옆의 크기는 여전히 잡힌다(테스트로 고정).
* **섹션 번호 `2.`가 표 셀 한가운데서 맨 정수로 잡혔다.** 목차 번호를 통과시키는
  규칙을 넓히면 그 구멍으로 다른 숫자가 샌다. **제목에서 번호를 뗐다** —
  검토자는 이름으로 찾으므로 잃는 것이 작다.
* **산식의 파이프가 표를 깨뜨렸다** — `|전기|`가 셀 구분자로 해석된다.
  [ff83b3f](.)에서 한 번 밟은 자리를 또 밟았다.
* **역산 시가총액·PER·PBR의 출처가 재무제표로 표시됐다.** 역산 주가에서 파생된
  값이므로 배당공시가 원천이다([D19](#d19)). 잘못 표시하면 검토자가 종가로
  오인할 여지가 커진다.

<a id="d37"></a>
### D37 — 발간 표면을 Next.js + shadcn/ui로 옮긴다 ([D26](#d26) 실행)

[D26](#d26)은 "서버 렌더로 먼저 세우고 `/api/*`는 Next.js가 나중에 그대로
호출한다"고 적어뒀다. 이건 그 계획의 **실행**이지 번복이 아니다. 버린 코드도
없다 — `/api/jobs`·`/api/search`·`/api/reports`가 그대로 프런트의 입구가 됐다.

계기는 사용자 요청("visual template을 바꾸고 싶다")이었고, 목적지는 이미
`surfaces/ra-tool-v0/architecture.md`에 `Next.js 15 (App Router, TypeScript,
Tailwind)`로 적혀 있었다. shadcn/ui는 그 스택의 표준 컴포넌트 모음이다.

**① 정적 익스포트 · 컨테이너 하나.**

Next.js를 별도 서버로 띄우지 않는다. `.arc-store`(추정 이력)가 볼륨에 있어야
하고 corpCode 캐시·LLM 예산이 **프로세스 메모리**에 있어서, 서비스를 둘로
쪼개면 셋 다 깨진다. `output: 'export'`로 빌드해 FastAPI가 `StaticFiles`로
서빙한다. Node는 Docker 빌드 스테이지에만 있고 **런타임에는 없다.**

정적 마운트는 반드시 `/api/*` **뒤에** 등록한다. `/`에 붙으므로 먼저 걸리면
API 요청을 정적 파일 조회가 가로챈다.

**② 노트 본문의 숫자는 여전히 서버가 만든다 — React가 다시 만들지 않는다.**

이 이관에서 가장 중요한 제약이다. `render_html()`이 수치마다
`<span class="num" data-key … data-url>`을 붙여 내보내고, React는 그 문자열을
`dangerouslySetInnerHTML`로 **그대로 주입**한 뒤 `element.dataset`을 읽어
팝오버를 붙인다.

React에서 숫자를 다시 포맷하면 레지스트리를 거치는 경로가 둘이 되고, 그 순간
G0가 지키던 것이 화면에서 무너진다. 차트도 마찬가지다 — `render/charts.py`가
만든 인라인 SVG를 그대로 넣는다([D32](#d32)).

따라서 `web/app/note.css`의 선택자(`.num`, `.num--estimate`, `.note h2/table/
blockquote`)는 **Tailwind 유틸리티로 대체할 수 없다.** 서버가 내보내는 고정
클래스명과 정확히 맞아야 한다. 값만 shadcn 토큰에서 가져온다.

**③ shadcn은 Radix가 아니라 Base UI를 쓴다.**

`base-nova` 스타일은 `@base-ui/react` 기반이다. 팝오버 앵커를 Radix식으로
짜다가 빌드가 깨져서 알았다. 결과적으로는 더 낫다 — Base UI의 Positioner는
`anchor`로 **DOM 엘리먼트를 직접** 받으므로, 서버가 만든 `<span>`을 그대로
넘기면 충돌 회피(화면 밖으로 나가면 뒤집기)까지 맡길 수 있다. 이전 화면은 그
좌표를 손으로 계산했다.

`create-next-app`이 넣는 `web/AGENTS.md`가 "이 버전은 네가 아는 Next.js가
아니다, `node_modules/next/dist/docs/`를 읽어라"라고 경고한다. **지우지 말 것.**
이 발견이 거기서 나왔다.

**④ `--primary`는 무채색으로 둔다 — 화면의 유일한 파란색은 `.num`이다.**

처음엔 기존 파란색(`#2563eb`)을 primary에 넣었다. 그러면 버튼·링크·수치가
전부 같은 색이 되어 **"되짚을 수 있다"는 신호가 묻힌다.** shadcn 기본 무채색을
쓰면 페이지에서 색을 가진 것이 출처 있는 숫자와 의미색 넷(`ok`/`bad`/`warn`/
`est`)뿐이다. 출처 링크도 `primary`가 아니라 `--num`을 쓴다.

**⑤ no-JS 폼 POST를 버린다.**

이전 화면은 JS 없이도 동작했고(`POST /`), `/api/jobs`는 진행 표시를 위한
향상이었다. SPA는 그 성질을 잃는다. 인증 뒤의 내부 도구라 비용이 작다고 보고
포기했다 — **기록해 두는 이유는 이게 의도된 손실이기 때문이다.**

**⑥ 부수 발견: 진행 표시가 죽어 있었다.**

`#prog`·`#steps`·`#elapsed`의 마크업과 CSS는 있는데 **이를 구동하는 JS가
없었다.** 서버 SSE는 완성돼 있고 테스트도 있는데(`web/jobs.py`,
`tests/test_jobs.py`) 브라우저에서 부르는 쪽이 없어서, 폼 POST가 끝날 때까지
그냥 기다렸다. React가 첫 소비자다. 흐름은
`POST /api/jobs` → SSE 구독 → `done` → `GET /api/jobs/{id}/result`.

마지막 조회를 위해 엔드포인트를 하나 더했다. `/api/reports`는 동기라 30~40초를
붙들어 진행 표시를 붙인 이유가 사라진다. 아직 안 끝난 작업에는 409를 준다 —
200에 빈 결과를 주면 화면이 **그걸 결과로 받는다.**

**실측**: 회귀 7종목 전부 게이트 통과, 534 테스트 통과. LG전자 기준 레지스트리
158건 · `.num` 194개 · `data-url` 208개. LLM을 켜면 미검증 레인([D31](#d31))이
blockquote로 갈라지고 그 문단 본문에 숫자가 없다.

**⑦ 출처는 마우스와 키보드 양쪽으로 연다.**

이관 직후에는 마우스로만 열렸다. "숫자를 누르면 출처가 나온다"가 이 제품의
논증인데, 경로가 하나뿐이면 키보드 검토자에게는 그 논증이 **아예 없는 것과
같다.** `render_html()`이 `.num`에 `role="button" tabindex="0"`을 붙이고
화면이 Enter·Space를 받는다. 닫으면 원래 숫자로 포커스를 돌려준다.

마크다운 인라인이라 `<button>`을 쓰면 문단·표 셀 레이아웃이 흔들린다. `span`에
역할만 부여했다. 테스트로 고정했다(`test_number_is_keyboard_reachable`).

**남긴 것**: `src/arc/web/templates/index.html`은 한 릴리스 동안 커밋에
남긴다(롤백 경로). 서빙되지 않는다.

<a id="d38"></a>
### D38 — RA 도구 표면으로 전환. [D8](#d8)이 기각한 것은 "RA 도구"가 아니라 **"엔터프라이즈로 파는 RA 도구"**였다

**결정**: 목표 제품을 **RA 도구 표면**으로 바꾼다. 판매는 증권사 seat이 아니라 **RA 개인 결제**다. 발간 표면은 중단하지 않되 목적을 바꾼다 — 산출물이 아니라 **RA 접촉의 명분**이다.

**D8을 뒤집는 근거.** D8은 RA 도구를 *"증권사 내부 도구 / 유료 seat / 영업 필요"*로 규정하고 보류했다. 기각의 실질적 근거는 마지막 항목 하나였다 — *"개인 개발자가 증권사 엔터프라이즈 영업을 뚫어야 함"*.

**그 장벽은 지금도 그대로다. 바뀐 것은 장벽이 아니라 판매 경로다.**

RA가 **개인 계정으로 결제해 자기 노트북에서 쓰는 도구**라면 증권사 영업이 필요 없다. 구매 절차도, seat 계약도, 보안 심사도 없다. D8이 테이블에 올린 선택지는 (a) 발간과 (b) 엔터프라이즈 RA 도구 둘뿐이었고, **(c) 개인 셀프서브는 검토되지 않았다.**

즉 D8은 틀린 결정이 아니라 **선택지가 빠진 결정**이었다.

**발간 표면을 목표에서 내리는 근거.** 발간은 *"RA의 업무가 재설계되는가"*를 검증하지 못한다 — **독자가 RA가 아니라 투자자이기 때문이다.** 그리고 [corpus/FINDINGS.md](../corpus/FINDINGS.md)가 결과 기반 품질 정의를 기각한 이상, 발간을 계속해도 *"좋은 리포트란 무엇인가"*에는 답이 나오지 않는다. **그 답은 RA의 반려 사유에 있지 주가 경로에 있지 않다.**

**규제 부담이 내려간다.** 유료 발간은 유사투자자문업 경계에 접근한다 — [D5](#d5)가 무료·일방향을 고른 이유가 그것이다. 반면 **라이선스 보유 전문가가 쓰는 도구**는 컴플라이언스 책임이 사용 기관에 남는다.

**발간 표면 처리 — 폐기가 아니라 용도 변경.** 발간물은 접근 명분이 된다: *"제 도구를 써보시겠어요"*가 아니라 ***"제가 이걸로 만든 리포트인데 봐주시겠어요"***. [D8](#d8) 근거 4번(*"RA 인터뷰를 발간 경험을 갖고 가면 질문의 밀도가 다르다"*)은 그대로 유효하다.

**미리 적는 실패 조건.** RA 인터뷰에서 **5명 중 3명 이상이 "회사가 사줘야 쓴다"**고 답하면 개인 셀프서브 전제가 무너진다. 그때는 D8로 되돌리거나 엔터프라이즈 경로를 다시 연다.

**다음 검증.** 인터뷰에서 직접 묻는다 — *"회사가 사줄 때까지 기다리시겠어요, 본인 카드로 쓰시겠어요? 얼마까지면 그냥 쓰시겠어요?"* **여기서 나온 숫자가 가격이 된다.**

**미구축.** 개인 결제 배관은 없다. 가격도 정해지지 않았다. 둘 다 인터뷰 결과를 입력으로 받는다.
