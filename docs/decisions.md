### D8 — 제품 구조: 공통 엔진 + 표면 2개, 발간 먼저

**결정**: 데이터·계산·게이트·서술을 **하나의 엔진**으로 짓고, 그 위에 표면을 둘 올린다. **발간 표면을 먼저** 만든다.

```
                 ┌─────────────────────────────┐
                 │  공통 엔진                   │
                 │  데이터 · 계산 · 게이트 · 서술 │
                 └──────────┬──────────────────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
    ┌───────────────────┐      ┌────────────────────┐
    │ 발간 표면 (지금)    │      │ RA 도구 표면 (보류)  │
    │ 세미오토 자체 발간  │      │ 증권사 내부 도구     │
    │ 무료·일방향        │      │ 유료 seat          │
    │ 인허가 제로        │      │ 영업 필요           │
    └───────────────────┘      └────────────────────┘
```

**근거**:
1. 발간은 **인허가 제로로 당장 시작 가능**하고 유통 경로가 필요 없다 (D5)
2. 7/25 판단 그대로 — *"(b)로 시작하면 발간 실적·골든셋·검증 파이프라인이 자산으로 축적 → 이후 (a) B2B·증권사 제휴·유료화 어느 쪽으로든 전환 가능한 옵션 보존"*
3. [research/02-report-quality.md](research/02-report-quality.md) §3의 **추정 정확도 추적**이 자체 발간에서도 그대로 축적된다. 내 추정 vs 실제 실적 이력이 곧 B2B 전환 시의 신뢰 자산이다
4. RA 인터뷰를 발간 경험을 갖고 가면 질문의 밀도가 다르다

**보류 처리**: RA 도구 표면의 v0 설계는 [surfaces/ra-tool-v0/](surfaces/ra-tool-v0/)에 보존. [research/04-reshape-interview.md](research/04-reshape-interview.md) §7의 가설 H1이 인터뷰로 검증되면 되살린다.

<a id="d9"></a>
### D9 — 목표주가: 엔진은 계산하고, 표면이 정책을 정한다

**충돌이었던 것**: D4는 "단일 목표주가 출력 금지"인데, [research/03-valuation-boundary.md](research/03-valuation-boundary.md)는 "밸류에이션 계산까지 포기한 것은 과잉"이라 결론.

**해소**: 두 층을 분리한다.

| 층 | 정책 |
|---|---|
| **엔진** | 밸류에이션을 **계산한다** — 3표 전개, 멀티플 밴드, 분해 항등식, 시나리오, 교차검증. 모든 입력에 `source` 태그 (`estimate_model` / `human_assumption` / `sec_fact`) |
| **발간 표면** | 단일 목표주가·투자의견 **출력 차단** (D4 유지). 시나리오 3개 + 감도표 + 산식 공개만. G0가 강제 |
| RA 도구 표면 | 계산 제공 + 애널리스트가 명시적으로 채택. 자동 복사 금지 |

즉 **엔진의 능력과 표면의 정책이 다르다.** D4는 발간 표면의 정책으로 유지되고, 엔진은 계산을 온전히 제공한다.

검증된 세부: `PBR = PDR × ROE × 배당성향`은 근사가 아니라 **항등식**이다 (수치 검증 완료). 4개 중 3개를 넣으면 나머지가 결정되므로 정합성을 코드가 강제할 수 있다. 마진 브리지의 `reconciliation` 패턴과 같은 성질.

<a id="d11"></a>
### D11 — 골든셋 출발점: SMIC 15건 + 선택 효과 보정

7/25가 *"한국어 리포트 품질 벤치마크는 전무하므로 골든셋 자체가 이 프로젝트의 핵심 데이터 자산"*이라 했다. 그 공백의 첫 채움으로 SMIC(서울대 투자 학회) 리포트 15건 분석을 확보했다 ([research/01-benchmark-smic.md](research/01-benchmark-smic.md)).

**다만 그대로 규범으로 쓰면 안 된다.** SMIC는 학회라 **쓰고 싶은 종목을 골라서** 쓴다. 배정 커버리지가 아니다:

| 지표 | 시장 (sell-side) | SMIC 15건 | 해석 |
|---|---|---|---|
| 매수 비중 | 93.1% | 100% | **선택 효과** — 편향이 아님 |
| 내재 상승여력 | 31% | 109.0% | 선택 효과 + 소형주 편중(10건 중 6건 시총 1조 미만). 잔여분 미확인 |

**채택 방식**: 구조는 학습하고 논조는 학습하지 않는다.

| 층 | 판단 |
|---|---|
| 구조 (추정 정밀도, 세그먼트 분해, P·Q 분해, 밸류에이션 논증 사슬, 부록 구성) | ✅ 골든셋으로 사용 |
| 논조·레지스터 (확신 표현, 상승여력 규모, rating 서술) | ❌ 제외 |

**결핍 확인**: 15건 전부가 확신에 찬 매수 아이디어라 **중립·부정 톤 참조가 없다.** 별도 코퍼스가 필요하다.

<a id="d12"></a>
### D12 — 추정 정확도·revision 추적을 최우선 차별화로 승격

7/25가 이미 *"전 보고서 대비 추정 변화 추적 — 이것이 진짜 차별화"*라 했고, 템플릿 §5에도 반영돼 있다. 7/30~31 분석이 이를 **두 개의 독립 증거로 보강**했다:

| 증거 | 내용 |
|---|---|
| **FnGuide Best Analyst 루브릭** | 100점 중 **40점이 실적 추정 정확도** — 최대 단일 배점. 70%가 검증 가능한 예측 성과 |
| **SMIC 15건 계량** | `추정` 855회, `26E/27E/28E` **15/15건**. 컨센서스 인용은 5/15건뿐 (자체 추정이 표준) |
| 시장 실패 데이터 | 하향 조정이 상향보다 **72일 vs 61일** 지연. 신뢰가 무너지는 지점 |

**추가 결정 — 정합성 표시 3종** ([research/02-report-quality.md](research/02-report-quality.md) §3.5의 C안):

매수 편향 시장에서 rating에 개입하지 않고 **추정·목표주가·rating의 모순만 계산으로 드러낸다.**

| 표시 | 겨냥 |
|---|---|
| 목표주가 ↔ 추정 정합성 (괴리 %) | 근거 없는 목표주가 |
| **revision 정합성** ("추정은 하향, 목표주가는 무변동") | 72일 하향 지연 |
| 상대 대조 (내재 상승여력 vs 시장 평균 31%) | 낙관 편향 자각 |

**매도 의견을 유도하지 않는다.** 93.1% 매수는 발행사 관계·IB·법인영업에서 오는 제도 제약이고(외국계 지점은 같은 시장에서 15~22%), 도구가 고칠 수 없다. 도구는 계산만 하고 판단은 사람이 한다.

**구현 상태**: ✅ Number Registry + G0 구현 완료. 정합성 표시 3종은 미착수 — 추정 레이어가 선행되어야 한다.

### D2 보강 — US 확장 시 SEC만으로 부족하다

SMIC의 해외 커버 5건 중 **3건이 SEC 밖**이었다: Soitec(파리), Aixtron(프랑크푸르트), Global Unichip(타이베이). AI 인프라 밸류체인을 파고들면 유럽 장비사와 대만 디자인하우스로 갈 수밖에 없다.

KR 우선(D2)은 유효하나, **US 확장을 "SEC 어댑터 하나 추가"로 계획하면 안 된다**는 경고를 로드맵에 남긴다.

<a id="d3-보강"></a>
### D3 보강 — 리포트는 재무제표에서 출발하지 않는다

SMIC 15건은 두 테마로 배타적으로 갈렸다: **AI 인프라 병목**(10건, `병목` 220회) / **밸류업·지배구조**(5건, `승계` 191회·`배당` 317회). 논리 흐름은:

```
매크로·정책 서사 → 산업 구조(밸류체인·병목) → 종목 선정 → 재무 추정 → 밸류에이션
```

재무 지표는 **논지의 증거**이지 출발점이 아니다. 실증: 손익계산서에서 앵글을 생성하면 NVDA FY2025(매출 폭증)와 TSLA(마진 하락)가 **글자까지 동일한 앵글 3개**를 받는다.

S2(재무분석 → thesis.json) 설계 시 반영할 것 — thesis는 산업·정책 입력을 받아야 한다.

### D14 — S4 서술 모델: GPT-5.6 Luna (최저가 티어)

**실측 근거** (2026-08-01, 삼성전자 FY2025, 5회 반복):

| 지표 | 결과 |
|---|---|
| G0 **1차 통과율** | **100%** (5/5) |
| 숫자 리터럴 유출 | **0%** |
| 카탈로그 밖 키 | 0% |
| 금지어(rating·단정) | 0% |
| JSON 파싱 실패 | 0% |
| 건당 비용 | **$0.0019** |
| 지연 | 9~12초 |

**가장 위험했던 가정이 검증됐다** — "LLM이 숫자 리터럴 없이 쓸 만한 한국어를
만들 수 있는가". 최저가 티어에서 1차 통과율 100%다.

이게 가능한 이유는 Number Registry가 LLM의 역할을 좁혀뒀기 때문이다. 계산도
검증도 하지 않고 정해진 어휘로 문장만 조립하므로, 플래그십이 필요한 작업이
아니다. 비용도 같은 이유로 무의미한 수준이다 — 100건/월에 $0.19.

설계서 추정($0.5~0.9/건)의 **1/300**이다. 추정 당시엔 S1 정규화·S2 분석·
S4 병렬 작성·S5 LLM 검증을 모두 LLM으로 가정했는데, 실제로는 S4만 LLM이고
나머지는 결정론 코드다.

**비용은 이 규모에서 제약이 아니다.** 플래그십(Sol)을 써도 100건/월 $3.45,
코스닥 전종목 분기 갱신도 월 $20 수준이다. 모델 선택은 비용이 아니라 품질로
한다. 다만 G1/G2 LLM 검증을 붙이거나 공시 원문을 프롬프트에 넣으면 이 계산은
깨진다.

<a id="d15"></a>
### D15 — 카탈로그에 방향(부호)을 포함한다

초판은 카탈로그에서 값을 완전히 뺐다. 그랬더니 LLM이 방향을 알 수 없어
모든 문장을 "변동했다"로 썼고, 지표를 하나씩 읊는 읽히지 않는 글이 나왔다.
[research/01-benchmark-smic.md](research/01-benchmark-smic.md) §3이 진단한
"손익계산서에서 출발하면 템플릿이 나온다"가 그대로 재현됐다.

**방향은 크기가 아니다.** 결정적 코드가 부호에서 뽑은 사실이므로 환각이 아니고,
크기는 여전히 노출되지 않는다. 카탈로그에 `direction`(증가/감소/보합)을 넣고
프롬프트에 "정도 표현(크게·소폭·급격히)은 금지"를 추가했다.

결과: 통과율 100%를 유지하면서 문장이 지표를 **연결**하기 시작했다
("원가 부담 완화가 총이익률 개선으로 연결", "영업단의 개선이 순이익단까지").

**남은 한계**: 여전히 산업·정책 서사가 없다. 프롬프트에 재무 카탈로그만 있어
LLM이 쓸 수 있는 것이 재무 기계학뿐이다. 세그먼트·공시 본문·산업 데이터가
붙어야 [research/01](research/01-benchmark-smic.md) §3이 말한 진짜 리포트가
된다. 이건 데이터 레이어 확장 과제이지 모델 문제가 아니다.
