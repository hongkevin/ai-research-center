> 제품명은 working name입니다. §11 오픈 아이템 참조.

## 1. 문제 정의

### RA의 하루

국내 증권사 리서치센터의 RA는 애널리스트가 커버하는 종목의 실무를 맡습니다. 리포트 1건이 나가기까지 RA가 실제로 하는 일:

1. 공시가 올라오면 재무제표를 열어 매출·원가·영업이익·R&D·SG&A를 스프레드시트로 옮긴다
2. YoY, 마진, 원가율을 계산한다
3. 애널리스트에게 초안을 올린다
4. 애널리스트가 **"이 숫자 출처 어디야?"** 라고 묻는다 → 공시를 다시 열어 찾는다
5. 준법감시인 심사에서 문구가 걸린다 → 수정 → 재심사

해외 종목을 커버하면 여기에 하나가 더 붙습니다. **공시가 영어입니다.** 10-K는 100페이지가 넘고, 같은 개념이 회사마다 다른 계정명으로 잡혀 있습니다. `RevenueFromContractWithCustomerExcludingAssessedTax`인지 `Revenues`인지에 따라 숫자가 달라집니다. 손으로 옮기는 과정에서 실수가 나면 리포트 신뢰가 깨집니다.

### 병목의 위치

"요약을 빨리 쓰는 것"이 병목이 아닙니다. 실제 병목은:

| 질문 | 현재 해결 방식 | 걸리는 시간 |
|---|---|---|
| 이 숫자가 공시에서 확인되는가 | 공시 원문을 직접 열어 대조 | 종목당 30분~2시간 |
| 이 계산값은 어떤 공식으로 나왔는가 | 스프레드시트 셀 수식을 역추적 | 질문받을 때마다 반복 |
| 이 문구가 투자권유로 읽히는가 | 심사에 올려보고 반려되면 안다 | 반려 1회당 반나절~1일 |
| 작년 대비 이익률 변화의 원인이 무엇인가 | 감으로 쓰고 근거를 나중에 찾는다 | — |

세 번째와 네 번째가 특히 비쌉니다. 반려는 발행 일정을 밀고, 근거 없는 원인 설명은 리서치센터의 평판 리스크입니다.

### 왜 ChatGPT로 안 되는가

RA들은 이미 LLM을 씁니다. 그런데 리포트에 못 씁니다. 세 가지 이유:

1. **숫자가 틀립니다.** LLM은 "매출 1,304억 달러"를 자신 있게 만들어냅니다. 확인 없이 리포트에 넣을 수 없습니다.
2. **출처가 없습니다.** 애널리스트가 출처를 물으면 답을 못 합니다. 결국 직접 다시 찾아야 하고, 그러면 시간을 아낀 게 아닙니다.
3. **감사 추적이 없습니다.** 증권사 내부 감사에서 "이 리포트의 숫자는 어디서 왔는가"에 답할 수 없습니다.

**이 세 가지를 구조적으로 해결하는 것이 이 제품의 전부입니다.**

## 2. 타겟 사용자

### 주 사용자: 국내 증권사 리서치센터 RA

애널리스트의 커버리지 실무를 담당합니다. 리포트를 직접 쓰지만 최종 의견과 서명은 애널리스트가 합니다. 도구 구매 결정권은 없지만 도구 선택에 강한 영향력이 있습니다.

### 페르소나 A — 해외주식 담당 RA (초기 핵심 타겟)

미국 기술주 8~15종목을 커버합니다. 실적 시즌에는 주당 2~3건의 리포트 초안을 씁니다.

- **가장 큰 고통**: 영어 공시에서 숫자를 옮기는 시간, 그리고 옮긴 숫자가 맞는지에 대한 불안
- **현재 도구**: Bloomberg 터미널(있으면), 엑셀, ChatGPT(숫자는 안 믿고 문장만)
- **이 제품으로 바뀌는 것**: 티커 입력 → 출처가 붙은 재무표 → 초안 골격까지 자동. 숫자 대조 작업이 사라짐

이쪽을 초기 wedge로 잡습니다. 국내 데이터는 에프앤가이드·와이즈리포트가 이미 표준이라 정면 경쟁이지만, **SEC 기반 검증 가능한 재무 레이어는 국내에 제대로 된 게 없습니다.**

### 페르소나 B — 국내주식 담당 RA (Phase 2)

KOSPI/KOSDAQ 종목을 커버합니다. 데이터 접근성은 A보다 낫지만(DART, 에프앤가이드) 초안 작성과 컴플라이언스 반려 문제는 동일합니다.

- **가장 큰 고통**: 반복적인 초안 작성, 준법감시인 반려 사이클
- **이 제품으로 바뀌는 것**: 초안 골격 + 발행 전 문구 사전 점검

### 인접 확장 경로 (Phase 3+)

RA 시장 자체가 작다는 리스크(§10)에 대한 대응입니다. 제품 핵심(출처가 붙은 숫자 + 근거 있는 문장 + 발행 전 점검)이 그대로 적용되는 인접군:

- 자산운용사 리서치 담당
- 상장사 IR 담당 (자사·경쟁사 지표 비교 자료)
- 금융 전문 기자 (숫자 인용 검증)
- 애널리스트 본인 (RA가 없는 소규모 하우스)

## 4. 제품 원칙

네 가지. 기능 결정이 원칙과 충돌하면 원칙이 이깁니다.

### 원칙 1 — 숫자는 AI가 만들지 않는다

LLM은 초안에서 숫자 리터럴을 쓸 수 없습니다. `{{fact:sec:NVDA:FY2025:revenue_yoy_growth}}` 같은 토큰만 쓸 수 있고, 렌더링 시점에 결정론 코어가 확정값으로 치환합니다. 미바인딩 숫자가 남아 있으면 초안이 거부됩니다.

프롬프트 지시가 아니라 **파이프라인 제약**입니다. 이 차이가 제품의 존재 이유입니다.

### 원칙 2 — 투자의견은 사람이 입력한다

목표주가와 투자의견은 리포트에 들어갑니다. 그러나 **시스템은 이것을 생성하지 않습니다.** 애널리스트가 직접 입력하고, 입력자와 시각이 감사 로그에 남습니다. LLM 경로에서 이 필드에 대한 쓰기는 스키마와 API 레이어에서 이중 차단됩니다.

모든 산출물에 고정되는 계약:

```json
{
  "ai_generated_opinion": false,
  "investment_opinion": {
    "source": "human_analyst",
    "entered_by": "<user_id>",
    "entered_at": "<iso8601>"
  }
}
```

> 해커톤 버전은 `recommendation: null`을 영구 고정했습니다. 내부 콘텐츠 도구라 의견 자체를 안 만들었기 때문입니다. RA용 제품에서는 의견 필드가 필요하되 **출처가 사람임을 증명**하는 쪽으로 경계를 옮겼습니다.

### 원칙 3 — 찾지 못한 값은 채우지 않는다

공시에서 확인되지 않는 숫자는 그럴듯하게 추정하지 않고 `omitted[]`에 이유와 함께 남깁니다. 표준 지표 모델이 맞지 않는 업종(금융업 등)은 억지로 적용하지 않고 `coverage.status: "limited"`로 표시하고 무엇이 왜 비었는지 밝힙니다.

기능 부족처럼 보이지만, 이게 신뢰의 근거입니다. JPM 예시(`../src/examples/facts/JPM.json`)에서 원가율/영업이익률 브리지를 만들 수 없다고 명시하고 41개 항목을 `omitted`에 남기는 동작이 이미 구현되어 있습니다.

### 원칙 4 — 프리체크는 심사를 대체하지 않는다

출력 라벨은 항상 `발행 전 프리체크`입니다. 위법/합법을 판정하지 않고, 심사필을 만들지 않습니다. 애매한 항목은 `준법감시인 확인 필요`로 올립니다. 최종 발행 판단은 사람이 합니다.

## 5. 경쟁 지형

| 경쟁자 | 강점 | 이 문제에 대한 공백 |
|---|---|---|
| **ChatGPT / Claude 직접 사용** | 즉시 사용 가능, 저렴, 문장 품질 좋음 | 숫자 환각, 출처 없음, 감사 추적 없음, 컴플라이언스 없음 |
| 에프앤가이드 / 와이즈리포트 (WiseFn·Quantiwise) | 국내 데이터 표준, 시장 신뢰, 광범위한 커버리지 | 정적 데이터 제공. 리포트 작성·문구 점검 지원 없음. 해외 공시 원문 추적 약함 |
| Bloomberg / FactSet / Refinitiv | 데이터 깊이, 글로벌 커버리지 | 고가, 영문 중심, **한국어 리포트 작성 지원 없음**, 국내 법령 프리체크 없음 |
| AlphaSense / Hebbia | 문서 검색·요약 우수, 기관 신뢰 | 미국 시장 중심. 한국어 리서치 문체 없음, 국내 자본시장법 매핑 없음 |
| 사내 자체 개발 | 워크플로 정합성 | 유지보수 부담, LLM·공시 파서 전문성 필요 |

### 실질 경쟁자는 ChatGPT입니다

에프앤가이드는 **보완재**입니다. 데이터를 대체하려는 게 아닙니다. Bloomberg를 대체하려는 것도 아닙니다.

실제로 뺏어야 하는 건 **RA가 ChatGPT 창에 공시를 붙여넣고 있는 시간**입니다. 그러니 비교 기준은 "Bloomberg보다 데이터가 많은가"가 아니라 **"ChatGPT보다 신뢰할 수 있는가"** 입니다.

### 차별점 4개

1. **숫자 환각을 구조적으로 차단** — 프롬프트가 아니라 아키텍처 불변식. 미바인딩 숫자가 있는 초안은 렌더링되지 않음
2. **한국어 리서치 문체** — 번역체가 아닌 국내 리포트 관행에 맞는 문장. 테넌트별 과거 리포트를 스타일 참조로 사용
3. **자본시장법 프리체크 + 감사 추적** — 국내 법령에 매핑된 결정론 룰. 누가 어떤 숫자로 무엇을 썼는지 전부 기록
4. **SEC + DART 단일 뷰** — 해외/국내를 같은 지표 모델로. 국내 도구는 해외가 약하고 해외 도구는 국내가 없음

## 6. 기능 범위

### MVP (Phase 1)

사용자에게 보이는 제품은 **리포트 초안 에디터** 하나입니다. Fact Layer는 그 아래 필수 인프라로 존재하며, 별도 기능으로 팔지 않습니다.

| 기능 | 왜 MVP인가 | 근거 자산 |
|---|---|---|
| **Fact Layer (SEC)** | 근거 있는 초안의 전제 조건. 이게 없으면 ChatGPT와 동일 | `edgar_financials.py` 재사용 |
| **종목 팩트 뷰** | RA가 숫자를 신뢰하려면 눈으로 확인해야 함. 엑셀 내보내기로 기존 워크플로 접속 | 동일 |
| **초안 에디터 + LLM 서술** | MVP의 가치 제안 그 자체 | `single_stock_packet.py`가 골격 생성 |
| **Numeric Token Binding + 검증 게이트** | 차별점 #1. 없으면 제품이 아님 | 신규 |
| **의견 입력 (사람 전용)** | 원칙 2. 없으면 실무에 못 들어감 | 신규 |
| **축소 프리체크 (실시간 경고)** | 반려 감소가 초안 도구의 가치와 직결 | `prepublication_precheck.py` |

> **축소 프리체크**란: 전체 리포트 화면 없이, 에디터 우측 패널에서 6개 룰을 문장 단위로 실시간 표시하는 것까지. 심사 요청 내보내기와 법령 매핑 상세 화면은 Phase 2.

### Phase 2

| 기능 | 왜 이 순서인가 |
|---|---|
| **Fact Layer (DART)** | 국내 커버리지로 TAM 확대. MVP에 넣지 않은 이유는 계정과목 매핑 리스크(§10)를 SEC로 제품 검증을 끝낸 뒤 감당하기 위함 |
| **프리체크 전체 리포트** | 법령 매핑 상세, 심각도 분류, 심사 요청 내보내기 |
| **감사 로그 뷰** | 증권사 조달 심사에서 요구됨. 팀 계약 전에 필요 |
| **초안 버전 비교** | 애널리스트 피드백 반영 이력 |

### Phase 3

| 기능 | 왜 이 순서인가 |
|---|---|
| **테마 보드 (Comps + Shortlist)** | `editorial_board.py`가 거의 그대로 재사용 가능하지만, 초안 도구로서의 제품 정체성이 먼저 확립돼야 함 |
| **팀 워크스페이스** | 공유 커버리지, 리뷰 플로우 |
| **VPC 리사이징** | 증권사 전사 계약 대응 |
| **차트 자동 생성** | `chart_brief`가 이미 있음. 실제 렌더링까지 |

### 명시적 비범위

- 목표주가·투자의견 **생성** (원칙 2)
- 기대수익률, 매수/매도 시그널
- 실시간 시세·가격 데이터 (공시 기반 제품이므로)
- 준법감시인 심사 대체 (원칙 4)
- 컨퍼런스콜 전사·뉴스 감성분석 (Phase 3 이후 검토)

## 7. 유저 스토리 (MVP)

### US-1 — 종목 팩트 확보
**RA로서** 티커를 입력하면 **다년 재무 지표를 출처와 함께 받고 싶다.** 공시를 직접 열어 대조하는 시간을 없애기 위해.

수용 기준:
- 티커 입력 후 재무표가 표시되고, 모든 원시 숫자에 accession number / XBRL 태그 / 공시 URL이 붙는다
- 모든 계산값에 `formula`와 입력값이 표시된다
- 확인되지 않은 값은 빈칸이 아니라 "공시에서 확인되지 않음"으로 표시된다
- 엑셀로 내보낼 수 있다

### US-2 — 제한 커버리지 인지
**RA로서** 표준 지표 모델이 맞지 않는 종목은 **그 사실을 명확히 알고 싶다.** 잘못된 지표를 리포트에 쓰지 않기 위해.

수용 기준:
- `coverage.status: "limited"`인 경우 화면 상단에 배너로 표시
- 무엇이 왜 비었는지, 대신 쓸 수 있는 지표가 무엇인지 표시
- 금융업(JPM 등)에 제조업식 원가율 브리지를 제안하지 않는다

### US-3 — 초안 골격 받기
**RA로서** 종목의 팩트에서 **바로 쓸 수 있는 앵글과 목차 후보를 받고 싶다.** 백지에서 시작하지 않기 위해.

수용 기준:
- 앵글 후보 3개 이상, 각각 첫 문장 / 독자 질문 / 전개 순서 포함
- 각 앵글에 근거 fact가 연결되어 있다
- 제목 후보 5개
- 피해야 할 단정 표현 목록

### US-4 — 초안 본문 생성
**RA로서** 선택한 앵글로 **한국어 초안 본문을 생성하고 싶다.**

수용 기준:
- 생성이 스트리밍으로 표시된다 (긴 대기 없음)
- 본문의 모든 숫자가 fact 토큰으로 바인딩되어 있다
- 미바인딩 숫자가 감지되면 자동 재생성되고, 재생성 후에도 남으면 사용자에게 표시된다
- 생성된 문장에 투자의견·목표주가가 포함되지 않는다

### US-5 — 숫자 출처 즉시 확인
**RA로서** 초안의 어떤 숫자든 **클릭 한 번으로 출처를 확인하고 싶다.** 애널리스트 질문에 즉시 답하기 위해.

수용 기준:
- 본문의 숫자가 칩(chip)으로 렌더링된다
- 클릭 시 팝오버로 값 / 계산식 / 입력값 / accession / 공시 URL 표시
- 공시 URL 클릭 시 원문으로 이동

### US-6 — 투자의견 입력
**애널리스트로서** 투자의견과 목표주가를 **내가 직접 입력하고, 그 사실이 기록되기를 원한다.**

수용 기준:
- 의견 입력은 전용 모달에서만 가능
- "AI가 생성하지 않음" 문구가 모달에 표시
- 입력자 ID와 시각이 기록되고 감사 로그에서 조회 가능
- LLM이 생성한 초안에는 이 필드가 비어 있다

### US-7 — 발행 전 문구 경고
**RA로서** 위험 문구를 **작성 중에 알고 싶다.** 심사 반려를 줄이기 위해.

수용 기준:
- 6개 룰 카테고리(단정 표현 / 투자권유 / 손실보전·이익보장 / 광고 고지 누락 / 해외주식 환율·세금 오인 / 고위험 레버리지·옵션 조장)가 문장 단위로 검사된다
- 검출 시 해당 문장이 강조되고 심각도가 표시된다
- 더 중립적인 대체 문구가 제안된다
- 출력 라벨은 `발행 전 프리체크`이며 심사 대체가 아님이 명시된다

### US-8 — 커버리지 관리
**RA로서** 내가 담당하는 종목을 **워크스페이스에 등록하고 싶다.** 매번 티커를 다시 입력하지 않기 위해.

수용 기준:
- 종목 추가/제거
- 신규 공시가 감지되면 홈에 표시
- 최근 작업한 초안 목록

## 9. 가격 모델

> **전체가 검증 필요한 가정입니다.** Design partner 3곳으로 검증한 뒤 확정합니다.

### 플랜

| 플랜 | 가격 | 포함 |
|---|---|---|
| **Pro** | 월 190,000원 / 석<br>(연납 20% 할인 → 월 152,000원) | 초안 생성 무제한(fair use), fact 조회 무제한, 축소 프리체크, 개인 워크스페이스 |
| **Team** | 월 160,000원 / 석 (5석 이상) | Pro + 공유 워크스페이스, 프리체크 전체 리포트, 관리자 감사 로그 |
| **Enterprise** | 연간 계약, 별도 견적<br>(기준선 연 5,000만원+) | Team + 전용 VPC 또는 온프렘, SSO, 커스텀 룰셋, 사내 문체 학습 |

### 가격 근거

**원가 측면**: LLM 원가가 seat 가격의 5% 미만입니다.

초안 1건 = 입력 약 10K 토큰(시스템 프롬프트 + fact context) + 출력 약 4K 토큰. `claude-opus-5` 단가($5 / $25 per MTok) 기준:

```
입력  10,000 × $5  / 1,000,000 = $0.050
출력   4,000 × $25 / 1,000,000 = $0.100
                        합계 ≈ $0.15 / 건
```

프롬프트 캐싱 적용 시(시스템 프롬프트 + fact context가 안정 프리픽스, 캐시 읽기는 약 0.1배) 재생성 경로의 입력 비용은 1/10로 떨어집니다. 실제 평균은 건당 **$0.08~0.15** 수준.

seat당 월 20~50건 → 월 **$2~8** (약 3,000~11,000원). seat 가격 190,000원의 **2~6%**.

**가치 측면**: 리포트 1건당 숫자 정리·검증·반려 대응에 2~4시간이 든다고 가정하면, RA 인건비 시간당 환산으로 월 2~3건만 단축해도 seat 비용을 회수합니다.

> ⚠️ **2~4시간은 추정치입니다.** Design partner에서 실측해야 합니다. 이 숫자가 무너지면 가격 구조 전체를 다시 봐야 합니다.

### 왜 seat 기반인가

- 사용량 과금은 RA가 "생성 버튼 누르기"를 주저하게 만듭니다. 초안 도구에서 그건 치명적입니다
- 시장이 좁으므로(§10) seat 단가가 높아야 합니다. 국내 RA 전체가 1,000명 규모라면 100% 점유해도 연 20억대입니다 — 저가 대량 전략이 성립하지 않습니다
- Enterprise 계약이 실제 수익 상한입니다. Pro/Team은 bottom-up 침투 경로입니다

## 10. 리스크와 완화

### R1 — DART 계정과목 매핑 커버리지 (가장 높음)

**리스크**: SEC는 us-gaap XBRL 태그로 표준화되어 있어 `RevenueFromContractWithCustomerExcludingAssessedTax` → `revenue` 매핑이 결정론적입니다. DART의 K-IFRS 계정과목명은 표준화가 약하고 회사·연도별로 다릅니다. 매핑 테이블 커버리지가 곧 제품 품질입니다.

**완화**:
- MVP에서 DART를 제외하고 SEC로 제품을 먼저 검증 (Phase 2로 이동)
- KOSPI200 우선 매핑, 커버리지를 측정 가능한 지표로 관리
- 미매핑 항목은 기존 `coverage.status: "limited"` + `omitted[]` 메커니즘으로 **정직하게 표시**. 추정하지 않음 (원칙 3)
- 원시 지표 9개 + 계산 지표 11개만 매핑 대상 → 범위가 유한함 ([01-ARCHITECTURE.md](../../surfaces/ra-tool-v0/architecture.md) §4 참조)

### R2 — RA 시장 규모가 작다

**리스크**: 국내 증권사 리서치센터 수와 하우스당 RA 인원을 곱하면 전체 시장이 수백~1,000명대로 추정됩니다. Pro seat 100% 침투 시에도 연 매출 상한이 낮습니다.

> 이 추정치는 **bottom-up 가정**입니다. 대형사 리서치센터당 RA 10~30명 × 주요 하우스 10~15곳. 실측 필요.

**완화**:
- Enterprise 계약을 실질 수익원으로 설계 (seat는 침투 경로)
- 인접군 확장 경로를 처음부터 아키텍처에 반영 — 자산운용사 RA, IR 담당, 금융 기자 (§2)
- 제품 핵심(출처 붙은 숫자 + 검증된 문장)은 "리포트"에 종속되지 않음. 다른 문서 유형으로 확장 가능

### R3 — 증권사 조달 사이클

**리스크**: 망분리, 보안 심사, 전자금융감독규정 대응으로 전사 계약은 6~18개월이 걸립니다. 1인 개발 초기에 감당 불가.

**완화**:
- 하이브리드 배포 전략 — 클라우드 SaaS로 개인/팀 seat부터 bottom-up
- 아키텍처를 처음부터 single-tenant 배포 가능하게 설계해서, 계약이 나올 때 코드 변경 없이 VPC로 리사이징 ([01-ARCHITECTURE.md](../../surfaces/ra-tool-v0/architecture.md) §8)
- 감사 로그를 1급 요구사항으로 취급 — 조달 심사의 핵심 항목

### R4 — LLM 문장이 사내 문체와 안 맞는다

**리스크**: 하우스마다 리포트 문체 관행이 다릅니다. 매번 전면 재작성해야 하면 시간을 아낀 게 아닙니다.

**완화**:
- 테넌트별 과거 리포트를 few-shot 스타일 참조로 사용 (테넌트 격리)
- 문체 가이드를 시스템 프롬프트의 안정 프리픽스에 두어 캐싱 이점 확보
- 초안은 "완성본"이 아니라 "골격 + 근거"라고 포지셔닝. 기대 관리

### R5 — 프리체크 오탐 / 미탐

**리스크**: 오탐이 많으면 무시하게 되고, 미탐이 있으면 신뢰가 깨집니다. 미탐이 특히 위험합니다 — 통과했는데 반려되면 도구를 안 씁니다.

**완화**:
- 룰셋을 버저닝하고 테넌트별 커스텀 룰 허용
- "심사 대체 아님"을 UI에 상시 표시 (원칙 4) — 도구가 최종 판단을 하지 않음을 명확히
- 반려 사례를 룰 개선 루프로 피드백

### R6 — Fact Layer가 커버하지 못하는 질문

**리스크**: "AI 수요가 폭발해서 매출이 늘었다" 같은 원인 설명은 공시 숫자만으로 검증 불가입니다. 그런데 리포트에서 가장 중요한 부분이 그것입니다.

**완화**:
- 이건 기능이 아니라 **경계**입니다. 숫자로 설명 가능한 것(마진 브리지)과 추가 확인이 필요한 것(가격 정책, 수요, 경쟁)을 분리해서 후자를 **확인 질문으로 남깁니다.** 이미 `follow_up_questions`와 `avoid_overclaims`로 구현되어 있습니다
- RA에게 "이 부분은 당신이 판단할 영역"이라고 명시하는 것이 오히려 신뢰를 만듭니다
